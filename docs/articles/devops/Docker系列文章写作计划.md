# Docker 系列文章写作计划

> 文档类型：写作计划 / 系列规划
> 系列目录：`docs/articles/devops/`
> 创建日期：2026-09-01
> 作者：ValidX Team

本计划在已发布的《Docker 从入门到实践：镜像、容器、Compose、网络一文搞懂》基础上，规划一个完整的 **Docker 系列**，覆盖从镜像构建到生产运维、从原理到生态的全部关键节点。系列文章可独立阅读，也有明确的依赖顺序，整体构成一条"**入门 → 深度 → 生产 → 生态 → 实战**"的学习链路。

| 维度 | 说明 |
|------|------|
| **目标读者** | 后端 / 运维 / 全栈开发者；会用命令但缺体系化认知的 Docker 使用者 |

**系列原则**：每篇独立可读（首段交代背景 + 前置依赖）、命令实测可跑、有完整代码示例、结尾有"坑位总结"。

## 三、阶段详解

### 阶段一：镜像与构建（02-04）

> 目标：读者能写出高质量 Dockerfile，能容器化真实 Java 应用，并懂得镜像安全红线。

#### 02 Dockerfile 生产级最佳实践：多阶段构建与镜像瘦身

- **前置依赖**：01（Dockerfile 基础指令）
- **核心内容**：
  1. 多阶段构建的三种模式（builder / test+build / 多平台）；
  2. 层缓存优化：依赖层分离、`COPY` 顺序、`--mount=type=cache`；
  3. 镜像瘦身实战：alpine / slim / distroless 对比、`dockerfile` 工具（Hadolint）检查、`dive` 分析镜像层；
  4. 构建上下文与 `.dockerignore` 进阶。
- **字数预估**：4000+｜**亮点**：给出"同一个 Go 应用 800MB → 20MB"的完整瘦身过程。
- **坑位总结**：alpine 的 glibc 兼容问题、`COPY --chown` 权限、时区镜像缺失。

#### 03 Java 应用容器化实战：Spring Boot + ValidX demo 从 0 到 1

- **前置依赖**：02
- **核心内容**：
  1. 分层构建 jar（`layertools` 拆 layer 缓存依赖）；
  2. 基础镜像选型：eclipse-temurin vs openjdk vs distroless，大小与 JDK 特性取舍；
  3. **JVM 与容器内存关系**：`-XX:MaxRAMPercentage`、cgroup 感知、OOM 规避；
  4. 非 root 用户、时区（`TZ=Asia/Shanghai`）、HEALTHCHECK 落地；
  5. 用真实 ValidX demo 应用演示：写 Dockerfile → 构建 → 启动 → 健康检查全流程。
- **字数预估**：4500+｜**亮点**：直接复用仓库内的 ValidX demo 作为示例，系列内互相印证。
- **坑位总结**：`spring-boot-maven-plugin` 分层打包参数、JVM 默认堆与容器限制不匹配、`Exec format error`（架构不匹配）。

#### 04 镜像安全：扫描、签名与软件供应链

- **前置依赖**：02、03
- **核心内容**：
  1. 漏洞扫描：Trivy / Grype / Docker Scout 接入方式与 CI 落地；
  2. Docker Content Trust：签名原理、`DOCKER_CONTENT_TRUST=1`、`docker trust` 命令；
  3. SBOM 与供应链：syft 生成 SBOM、SLSA 级别、`latest` 标签的危害；
  4. 基础镜像安全基线：最小化、固定 digest、非 root。
- **字数预估**：4000+｜**亮点**：给出一份"镜像安全 10 条红线"清单。
- **坑位总结**：扫描器的网络依赖、签名对镜像不可变性的要求、多阶段构建会掩盖中间层漏洞。

### 阶段二：编排（05-07）

> 目标：读者能用 Compose 编排真实多服务应用，搞懂网络与存储的底层行为。

#### 05 Compose 生产级配置：从 demo 到可上线

- **前置依赖**：01（Compose 基础）、02、03
- **核心内容**：
  1. 多环境配置：`.env` + 变量替换 + profile / override 文件；
  2. `depends_on` 与就绪等待：healthcheck + 条件（`condition: service_healthy`）；
  3. restart 策略矩阵（no / on-failure / always / unless-stopped）；
  4. 日志、资源限制、网络、卷的完整生产配置；
  5. 一个"后端 + 前端 + MySQL + Redis + Nginx"完整可上线栈。
- **字数预估**：4500+｜**亮点**：提供"开发 / 测试 / 生产"三份可切换的 compose 变体。
- **坑位总结**：`docker compose` 与 `docker-compose` 差异、健康检查超时、`.env` 不生效的常见原因。

#### 06 Docker 网络深入：五种通信模式全解析

- **前置依赖**：01（网络基础）
- **核心内容**：
  1. bridge / host / none / macvlan / overlay 五种模式逐个拆解与适用场景；
  2. 自定义 bridge 的 DNS 解析、容器名即域名；
  3. 端口映射 vs 容器直连：什么时候该映射、什么时候不该；
  4. 跨主机通信：overlay 网络（Swarm）与经典方案（calico/flannel）概念。
- **字数预估**：4500+｜**亮点**：用 `nsenter`/`ip` 命令"扒开"容器网络栈，讲清 veth pair 与 iptables。
- **坑位总结**：默认 bridge 无 DNS、`--network host` 下 `-p` 失效、端口冲突排查。

#### 07 数据持久化方案：卷、挂载、权限与备份恢复

- **前置依赖**：01（数据卷基础）
- **核心内容**：
  1. 命名卷 / 绑定挂载 / 匿名卷对比与选型；
  2. 文件权限问题：容器 UID vs 宿主 UID、`:ro`、SELinux（`:z`/`:Z`）；
  3. 数据库持久化实战：MySQL / PostgreSQL 卷 + 定时备份（`pg_dump`、`mysqldump`）+ 恢复演练；
  4. 卷迁移与备份：`docker run --volumes-from`、tar 打包。
- **字数预估**：4000+｜**亮点**：给出一键备份 + 恢复的脚本模板。
- **坑位总结**：权限 1000:1000 问题、`chown` 与容器重建、匿名卷泄漏。

### 阶段三：生产运维（08-10）

> 目标：读者能给容器上资源红线、日志规范与排障方法，具备上生产的能力。

#### 08 容器资源限制与监控：从 --memory 到 Prometheus

- **前置依赖**：01、05
- **核心内容**：
  1. `--memory` / `--memory-swap` / `--cpus` / `--pids-limit` 详解；
  2. `docker stats`、`docker events`、OOM 现象与排查（`dmesg`）；
  3. cgroup v2 下限制的差异；
  4. cAdvisor + Prometheus + Grafana 搭建容器监控面板。
- **字数预估**：4500+｜**亮点**：完整复现一次"容器 OOM"并展示从现象到根因的排查路径。
- **坑位总结**：swap 上限 vs 内存上限、JVM 不感知 cgroup（老版本 JDK）、`--pids-limit` 误伤。

#### 09 容器日志收集与管理：stdout 规范与 ELK/Loki

- **前置依赖**：01、05
- **核心内容**：
  1. 日志驱动矩阵：json-file / journald / syslog / local；
  2. **应用日志规范**：为什么容器里日志必须打 stdout/stderr；
  3. 日志轮转与大小限制（max-size / max-file）；
  4. 轻量方案：Loki + Promtail + Grafana 从零搭建；重量方案：ELK 简介。
- **字数预估**：4500+｜**亮点**：用 ValidX demo 改造日志输出，演示一条日志"从应用到面板"的完整链路。
- **坑位总结**：容器内写日志文件的坏处、json-file 默认无限增长、时区对日志时间的影响。

#### 10 容器排障实战手册：从日志到内核的分层排障

- **前置依赖**：06、07、08
- **核心内容**：
  1. 分层排障方法论：容器状态 → 日志 → 网络 → 资源 → 文件系统 → 内核；
  2. `docker inspect` 大法：解析 `State`、`Config`、`Mounts`、`NetworkSettings`；
  3. 高频故障复现与排查：启动失败、反复 Restarting、端口冲突、OOM、DNS 解析失败、卷权限、假死容器；
  4. 排障工具清单：`nsenter`、`strace`、`lsof`、`tcpdump` 在容器排障中的用法。
- **字数预估**：5000+｜**亮点**：6 个真实故障案例，每个都有"现象 → 排查 → 根因 → 预防"四段式。
- **坑位总结**：`docker restart` 掩耳盗铃、只看 `docker ps` 不看 `-a`、日志被轮转吞掉。

### 阶段四：CI/CD 与仓库（11-13）

> 目标：读者能搭建私有镜像仓库，把构建接入 CI，并掌握容器化发布流程。

#### 11 私有镜像仓库：Registry、Harbor 与镜像同步

- **前置依赖**：01（私有仓库基础）

- **字数预估**：4000+｜**亮点**：Harbor 双机房复制 + 保留策略的完整配置样例。

#### 12 Docker + CI/CD：GitLab CI / GitHub Actions 自动化构建

- **前置依赖**：02、04、11
- **核心内容**：
  1. CI 中构建的最佳姿势：BuildKit 缓存挂载（`--mount=type=cache`）、`docker buildx` 多平台构建；

  3. tag 策略与推送：`$CI_COMMIT_SHA`、`latest`、环境标签；

- **字数预估**：4500+｜**亮点**：直接用本仓库写一份可复用的 GitLab CI / GitHub Actions 模板。
- **坑位总结**：Docker-in-Docker vs socket 绑定、缓存命中率、CI 中镜像体积对拉取时长的影响。

#### 13 容器化发布策略：滚动更新、优雅停机与回滚

- **前置依赖**：05、12
- **核心内容**：
  1. 单机滚动更新：`docker compose up -d` 的更新行为与 `--no-deps` 技巧；

  3. **优雅停机**：SIGTERM 处理、Spring Boot 的 `graceful shutdown`、preStop 钩子、`docker stop` 超时；
  4. 回滚三板斧：旧镜像 tag、compose 版本控制、Swarm `--rollback`。
- **字数预估**：4000+｜**亮点**：演示"更新期间零中断"的完整配置（preStop 等待 + 健康检查摘流）。
- **坑位总结**：`docker stop` 默认 10s 强杀、无健康检查时流量打到未就绪实例、回滚忘带旧配置。

### 阶段五：原理与生态（14-16）

> 目标：读者理解容器底层原理，看清运行时与 K8s 生态全貌。

#### 14 容器原理揭秘：namespace、cgroup 与镜像分层

- **前置依赖**：01、08
- **核心内容**：
  1. 容器本质是"加了隔离的进程"：Linux namespace（PID / 网络 / 挂载 / UTS / IPC / User）；
  2. cgroup 资源隔离与限制；`unshare` / `nsenter` 手动体验；
  3. 镜像分层：overlayfs、写时复制（CoW）、层共享与缓存；
  4. 用 `strace`/`lsns` 验证"容器不是迷你虚拟机"。
- **字数预估**：5000+｜**亮点**：不依赖 Docker，用 `unshare` 手搓一个"容器"证明原理。
- **坑位总结**：PID 1 与僵尸进程、`docker exec` 是新进程而非 PID 1、容器内 `systemd` 不可用。

#### 15 Docker vs Podman vs containerd：容器运行时全景

- **前置依赖**：14
- **核心内容**：
  1. 运行时分层：Docker / containerd / runc / OCI 规范；
  2. Podman：daemonless、rootless、`podman-compose` 兼容；
  3. containerd：与 K8s 的关系、`ctr` / `nerdctl` 常用命令；
  4. 选型建议：什么时候继续用 Docker、什么时候迁移。
- **字数预估**：4000+｜**亮点**：命令对照表（docker ↔ podman ↔ nerdctl 一键迁移）。
- **坑位总结**：rootless 的端口与卷限制、containerd 无 docker CLI 生态、`--cgroup-manager` 差异。

#### 16 从 Docker 到 Kubernetes：概念对照与迁移

- **前置依赖**：01、05、14
- **核心内容**：
  1. 核心对象对照：Pod ≈ 容器组、Deployment ≈ 服务更新、Service ≈ 网络、Ingress ≈ 反向代理；
  2. compose 到 K8s 的迁移路径：`kompose`、minikube / kind 本地验证；
  3. 配置与机密：ConfigMap / Secret vs 环境变量；
  4. 什么时候需要 K8s：单机 vs 多机、自建 vs 托管（云厂商）。
- **字数预估**：4500+｜**亮点**：用同一套 ValidX demo，分别用 compose 和 K8s 部署，逐项对照。
- **坑位总结**：K8s 不是 Docker 的替代品（是编排层）、Pod 内多容器共享网络、`latest` 在 K8s 中的坑。
