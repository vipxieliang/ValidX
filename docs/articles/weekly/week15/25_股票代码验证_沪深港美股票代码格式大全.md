## 引言

如果你在做金融类应用（股票交易 App、资产配置系统、财经数据平台），表单里一定少不了一个字段——**"股票代码"**。但用户输入的 `600000`、`00700`、`AAPL` 到底对不对？不同的交易所规则天差地别，A股是6位数字，港股是4-5位数字，美股是1-5个字母。简单写一个 `^\d{6}$` 只能覆盖沪深，港股和美股就直接被挡在外面了。

更棘手的是，**同一个代码在不同市场可能代表完全不同的公司**——比如 `00700` 是腾讯控股（港股），而 `700` 如果按6位补齐成 `000700` 则是中国长城（深市）。代码格式错了，轻则查不到数据，重则误下单。

本文把**沪深港美四大交易所的股票代码规则**一网打尽，从正则表达式到 ValidX 的 `@StockCode` 注解，再到链式 API 的多市场分派校验，帮你建立一套完整的股票代码校验体系。

## 一、股票代码：金融市场中的"身份证"

### 1.1 股票代码的本质

股票代码（Stock Code / Ticker Symbol）是证券交易所为上市公司分配的唯一标识符。它的作用类似于互联网中的域名——人类可读、机器可解析、全球（或交易所内）唯一。

不同交易所的代码规则差异很大：

| 维度 | A股（沪深） | 港股 | 美股 |
|------|-----------|------|------|
| 字符类型 | 纯数字 | 纯数字 | 纯字母 |
| 长度 | 固定6位 | 4-5位 | 1-5位 |
| 是否区分板块 | 是（首字母区分） | 否 | 否 |
| 大小写敏感 | 不适用 | 不适用 | 不敏感 |

### 1.2 为什么需要精确校验

在金融系统中，股票代码校验不是"锦上添花"，而是**底线要求**：

- **防止误下单**：代码错了可能买到完全不同的股票；
- **数据一致性**：对接行情数据源（如 Wind、Bloomberg）时，代码格式不对会导致数据映射失败；
- **用户体验**：在用户输入阶段就给出明确反馈，而不是等提交后才发现错误；
- **监管合规**：某些场景下（如资管系统），错误的代码可能导致合规风险。

### 1.3 校验的两个层次

股票代码校验分为两层：

1. **格式校验**：长度、字符类型、前缀是否符合交易所规则——这是 ValidX `@StockCode` 做的事；
2. **存在性校验**：该代码是否对应真实存在的上市公司——这需要对接交易所或数据服务商的 API（如 Wind、东方财富）。

**本文聚焦第一层**：用正则 + 规则把格式不对的代码挡在门外。存在性校验属于业务层，不在本文讨论范围。

## 二、上海证券交易所（SSE）：6位数字，以6开头

### 2.1 交易所简介

上海证券交易所（Shanghai Stock Exchange，SSE）成立于1990年，是中国大陆两大证券交易所之一，也是全球市值排名前列的交易所。

### 2.2 股票代码规则

| 板块 | 代码范围 | 正则表达式 | 示例 |
|------|---------|-----------|------|
| 沪市主板 | `600`/`601`/`603`/`605` 开头 | `^6\d{5}$` | `600000`（浦发银行）、`601318`（中国平安） |
| 科创板 | `688` 开头 | `^688\d{3}$` | `688981`（中芯国际） |
| B股 | `900` 开头 | `^900\d{3}$` | `900901`（上海航空B股） |

### 2.3 ValidX 中的正则

```java
// 上海证券交易所股票代码格式 (6位数字，以6开头)
private static final Pattern SHANGHAI_PATTERN = Pattern.compile("^6\\d{5}$");
```

> **注意**：ValidX 的 `SHANGHAI_PATTERN` 用的是 `^6\d{5}$`，这意味着**所有以6开头的6位数字都通过**。严格来说，科创板（688开头）和B股（900开头）也是上海交易所的，但它们有独立的板块标识。如果你的业务需要区分板块，可以在 `exchanges` 参数中做更细粒度的控制。

### 2.4 常见误区

- **误区一**：以为 `600000` 到 `699999` 都是沪股——实际上 `600`、`601`、`603`、`605`、`688` 才是常见的，中间有断档；
- **误区二**：以为所有6位数字都是A股——深市也是6位，但开头不同。

## 三、深圳证券交易所（SZSE）：多板并行，以0、3、4开头

### 3.1 交易所简介

深圳证券交易所（Shenzhen Stock Exchange，SZSE）同样成立于1990年，以中小企业和创新型企业为主，创业板（300开头）是其特色板块。

### 3.2 股票代码规则

| 板块 | 代码范围 | 正则表达式 | 示例 |
|------|---------|-----------|------|
| 深市主板 | `000` 开头 | `^000\d{3}$` | `000001`（平安银行） |
| 中小板（已合并） | `002` 开头 | `^002\d{3}$` | `002415`（海康威视） |
| 创业板 | `300` 开头 | `^300\d{3}$` | `300001`（特锐德） |
| 深市B股 | `200` 开头 | `^200\d{3}$` | `200002`（万科B） |
| 北交所/新三板 | `430`、`83`、`87` 开头 | 特殊规则 | `430001`（大自然） |

### 3.3 ValidX 中的正则

```java
// 深圳证券交易所股票代码格式 (6位数字，以0、3或4开头)
private static final Pattern SHENZHEN_PATTERN = Pattern.compile("^[034]\\d{5}$");
```

这里的 `^[034]\d{5}$` 覆盖了深市主板（0开头）和创业板（3开头）。`4` 开头的代码（如部分新三板转板）也被包含在内。

### 3.4 沪深代码对比

| 特征 | 沪市 | 深市 |
|------|------|------|
| 长度 | 6位 | 6位 |
| 字符类型 | 纯数字 | 纯数字 |
| 开头特征 | 以 `6` 开头 | 以 `0`、`3`、`4` 开头 |
| 板块区分 | 首字母区分（6=主板，688=科创板） | 首字母区分（0=主板，3=创业板） |
| 重合可能 | **不存在** | **不存在** |

> **重要**：沪深两市的代码规则**没有交集**——不存在一个6位数字同时是沪市又是深市。这是由交易所成立时的代码规划决定的。

## 四、香港联合交易所（HKEX）：4-5位数字

### 4.1 交易所简介

香港联合交易所（Hong Kong Exchanges and Clearing Limited，HKEX）是全球重要的金融中心之一，汇聚了大量中国大陆（H股、红筹股）和国际公司。

### 4.2 股票代码规则

| 类型 | 代码规则 | 正则表达式 | 示例 |
|------|---------|-----------|------|
| 一般港股 | 4-5位数字 | `^\d{4,5}$` | `00700`（腾讯控股）、`09999`（网易） |
| 主板 | 0001-9999 | `^\d{4}$` | `0001`（长江实业） |
| 创业板（GEM） | 通常以 `08` 开头 | `^08\d{2,3}$` | `08081`（恒芯中国） |

### 4.3 ValidX 中的正则

```java
// 香港联合交易所股票代码格式 (4-5位数字，可能以0开头)
private static final Pattern HONG_KONG_PATTERN = Pattern.compile("^\\d{4,5}$");
```

港股代码的特点是**前导零有意义**。`00700` 和 `700` 不是同一个代码——在港股系统中，`00700` 是腾讯，而 `0700` 也是腾讯（因为港股代码不足5位时前面补零）。但严格来说，港交所的代码是**不带前导零的4-5位数字**，`00700` 这种写法是系统展示时的格式化结果。

### 4.4 A股 vs 港股的代码区别

| 特征 | A股（沪深） | 港股 |
|------|-----------|------|
| 长度 | 固定6位 | 4-5位 |
| 前导零 | 无（600000是6位） | 可能有（00700是5位） |
| 字符类型 | 纯数字 | 纯数字 |
| 区分度 | 首字母区分板块 | 无板块前缀规律 |

## 五、纽约证券交易所（NYSE）：字母代号

### 5.1 交易所简介

纽约证券交易所（New York Stock Exchange，NYSE）是全球最大的证券交易所之一，以字母代号（Ticker Symbol）标识上市公司，是美股的典型特征。

### 5.2 股票代码规则

| 类型 | 代码规则 | 正则表达式 | 示例 |
|------|---------|-----------|------|
| 普通股票 | 1-5个大写字母 | `^[A-Z]{1,5}$` | `AAPL`（苹果）、`MSFT`（微软） |
| 类别股 | 字母 + `.` + 字母 | `^[A-Z]{1,5}(\.[A-Z])?$` | `BRK.A`（伯克希尔A类）、`BRK.B`（伯克希尔B类） |
| 特殊代码 | 含 `$` 或 `=` | 复杂规则 | `FACS`（某些ETF） |

### 5.3 ValidX 中的正则

```java
// 纽约证券交易所股票代码格式 (1-5个字母，可能包含点号)
private static final Pattern NEW_YORK_PATTERN = Pattern.compile("^[A-Z]{1,5}(\\.[A-Z])?$");
```

### 5.4 美股代码的特点

- **不区分大小写**：`aapl` 和 `AAPL` 是同一个代码，但标准写法是大写；
- **含有点号**：类别股（Class Shares）用 `.A`、`.B` 区分，如 `BRK.A` 和 `BRK.B`；
- **长度灵活**：从1位到5位都有，不像A股固定6位；
- **无板块前缀**：不像A股用首字母区分板块，美股板块由交易所上市规则决定。

## 六、四大交易所股票代码格式对照总表

| 交易所 | 代码示例 | 长度 | 字符类型 | 首字符规则 | ValidX 正则 |
|--------|---------|------|---------|-----------|------------|
| 上海证券交易所 | `600000` | 6位 | 数字 | 以 `6` 开头 | `^6\d{5}$` |
| 深圳证券交易所 | `000001` | 6位 | 数字 | 以 `0`、`3`、`4` 开头 | `^[034]\d{5}$` |
| 香港联合交易所 | `00700` | 4-5位 | 数字 | 无特殊规则 | `^\d{4,5}$` |
| 纽约证券交易所 | `AAPL` | 1-5位 | 字母 | 无特殊规则 | `^[A-Z]{1,5}(\.[A-Z])?$` |

### 6.1 区分度分析

四大交易所的代码规则**天然互斥**：

- 沪市（6位，以6开头）和深市（6位，以0/3/4开头）**不会冲突**（首字符不同）；
- 港股（4-5位数字）和美股（1-5位字母）**不会冲突**（字符类型不同）；
- A股（6位数字）和美股（字母）**不会冲突**（字符类型不同）。

这意味着：**一个股票代码最多只能匹配一个交易所的规则**，不存在"模棱两可"的情况。

## 七、ValidX 的 `@StockCode`：一行注解搞定多市场校验

### 7.1 注解的基本用法

ValidX 内置的 `@StockCode` 注解支持对四大交易所的股票代码进行格式校验：

```java
import io.github.vipxieliang.validx.annotations.StockCode;

public class StockTradeDTO {

    @NotBlank(message = "股票代码不能为空")
    @StockCode(message = "股票代码格式不正确")
    private String stockCode;
}
```

### 7.2 按交易所精确校验

如果业务场景只允许特定交易所的代码，可以用 `exchanges` 参数指定：

```java
public class StockTradeDTO {

    // 只接受沪深A股
    @StockCode(
        exchanges = { StockCode.Exchange.SHANGHAI, StockCode.Exchange.SHENZHEN },
        message = "仅支持沪深A股代码"
    )
    private String aStockCode;

    // 只接受港股
    @StockCode(
        exchanges = { StockCode.Exchange.HONG_KONG },
        message = "仅支持港股代码"
    )
    private String hkStockCode;

    // 只接受美股
    @StockCode(
        exchanges = { StockCode.Exchange.NEW_YORK },
        message = "仅支持美股代码"
    )
    private String usStockCode;
}
```

### 7.3 注解源码解析

```java
@Documented
@Constraint(validatedBy = { StockCodeValidator.class })
@Target({ METHOD, FIELD, ANNOTATION_TYPE, CONSTRUCTOR, PARAMETER, TYPE_USE })
@Retention(RUNTIME)
public @interface StockCode {
    String message() default "{io.github.vipxieliang.validx.annotation.stock.code}";

    Class<?>[] groups() default { };
    Class<? extends Payload>[] payload() default { };

    // 支持的交易所类型，默认支持所有交易所
    Exchange[] exchanges() default { 
        Exchange.SHANGHAI, 
        Exchange.SHENZHEN, 
        Exchange.HONG_KONG, 
        Exchange.NEW_YORK 
    };

    enum Exchange {
        SHANGHAI,   // 上海证券交易所
        SHENZHEN,  // 深圳证券交易所
        HONG_KONG, // 香港联合交易所
        NEW_YORK   // 纽约证券交易所
    }
}
```

### 7.4 验证器核心逻辑

`StockCodeValidator` 的实现思路是"**逐个交易所匹配，命中即通过**"：

```java
@Override
public boolean isValid(String value, ConstraintValidatorContext context) {
    if (value == null || value.isEmpty()) {
        return true; // 空值交给 @NotNull 处理
    }
    
    // 移除空格并统一大写
    String cleanValue = value.replaceAll("\\s+", "").toUpperCase();
    
    // 逐个交易所匹配
    if (exchanges.contains(StockCode.Exchange.SHANGHAI) 
            && SHANGHAI_PATTERN.matcher(cleanValue).matches()) {
        return true;
    }
    
    if (exchanges.contains(StockCode.Exchange.SHENZHEN) 
            && SHENZHEN_PATTERN.matcher(cleanValue).matches()) {
        return true;
    }
    
    if (exchanges.contains(StockCode.Exchange.HONG_KONG) 
            && HONG_KONG_PATTERN.matcher(cleanValue).matches()) {
        return true;
    }
    
    if (exchanges.contains(StockCode.Exchange.NEW_YORK) 
            && NEW_YORK_PATTERN.matcher(cleanValue).matches()) {
        return true;
    }
    
    return false; // 所有交易所都不匹配
}
```

> **设计要点**：`isValid` 采用 "**或逻辑**"——只要匹配**任意一个**指定交易所的规则就返回 `true`。这意味着如果你指定了多个交易所，代码只要符合其中任意一个即可通过。

## 八、链式 API：程序化场景下的灵活校验

### 8.1 基本链式校验

```java
import io.github.vipxieliang.validx.chain.ValidX;
import io.github.vipxieliang.validx.annotations.StockCode;

// 校验任意交易所的股票代码
ValidX.init()
     .field("股票代码")
     .isStockCode("600000");
```

### 8.2 指定交易所校验

```java
// 只校验沪市代码
ValidX.init()
     .field("沪市代码")
     .isStockCode("600000", StockCode.Exchange.SHANGHAI);

// 只校验深市代码
ValidX.init()
     .field("深市代码")
     .isStockCode("000001", StockCode.Exchange.SHENZHEN);

// 校验多个交易所（代码匹配任意一个即可）
ValidX.init()
     .field("股票代码")
     .isStockCode("00700", 
         StockCode.Exchange.SHANGHAI, 
         StockCode.Exchange.HONG_KONG);
```

### 8.3 链式 API 在业务层的应用

在实际业务中，经常需要根据用户选择的"市场"来校验不同规则：

```java
public class StockService {

    public void validateStockCode(String market, String code) {
        ValidX validator = ValidX.init()
            .withLocale(Locale.SIMPLIFIED_CHINESE);
        
        switch (market.toUpperCase()) {
            case "SH":
                validator.field("沪市代码").isStockCode(code, StockCode.Exchange.SHANGHAI);
                break;
            case "SZ":
                validator.field("深市代码").isStockCode(code, StockCode.Exchange.SHENZHEN);
                break;
            case "HK":
                validator.field("港股代码").isStockCode(code, StockCode.Exchange.HONG_KONG);
                break;
            case "US":
                validator.field("美股代码").isStockCode(code, StockCode.Exchange.NEW_YORK);
                break;
            default:
                // 未知市场，允许所有交易所
                validator.field("股票代码").isStockCode(code);
        }
        
        if (!validator.passed()) {
            throw new BusinessException(validator.getErrors().get(0));
        }
    }
}
```

## 九、实战中的边界场景与常见坑

### 9.1 港股代码的前导零

**问题**：用户输入 `700` 还是 `00700`？

**分析**：
- 港交所官方代码是**不带前导零**的（如 `700`）；
- 但很多系统（包括 ValidX）接受带前导零的格式（`00700`），因为 `^\d{4,5}$` 匹配4-5位数字；
- 如果用户输入 `0700`（4位），`HONG_KONG_PATTERN` 也会匹配。

**建议**：在业务层统一做格式化（补零到5位或去前导零），校验层保持宽松。

### 9.2 美股代码的大小写

**问题**：用户输入 `aapl` 还是 `AAPL`？

**分析**：
- ValidX 的 `StockCodeValidator` 在 `isValid` 中做了 `toUpperCase()`，所以大小写不敏感；
- 但建议前端统一转大写展示，避免用户困惑。

```java
// 验证器内部已处理大小写
String cleanValue = value.replaceAll("\\s+", "").toUpperCase();
```

### 9.3 空格和特殊字符

**问题**：用户从 Excel 复制代码时可能带空格，如 `" 600000 "`、`"AAPL "`。`

**分析**：
- ValidX 的正则中 `^` 和 `$` 会严格匹配整串，不会自动 trim；
- 但 `StockCodeValidator` 内部做了 `replaceAll("\\s+", "")`，所以空格会被自动移除；
- 如果需要在注解层面更严格，可以自定义验证器或额外处理。

### 9.4 同一代码多市场匹配

**问题**：`600000` 会同时匹配沪市和深市吗？

**分析**：
- `600000` 以 `6` 开头，只匹配 `SHANGHAI_PATTERN`（`^6\d{5}$`）；
- 深市规则是 `^[034]\d{5}$`，`6` 不在其中；
- 所以**不会同时匹配多个市场**。

### 9.5 "全市场" vs "指定市场"的策略

| 场景 | 推荐策略 | 代码示例 |
|------|---------|---------|
| 用户明确选了"市场" | 指定交易所校验 | `.isStockCode(code, Exchange.SHANGHAI)` |
| 用户没选市场 | 全市场自动匹配 | `.isStockCode(code)` |
| 需要反查市场 | 全市场匹配 + 命中后识别 | 自定义逻辑 |

### 9.6 格式校验 ≠ 存在性校验

**重要提醒**：`@StockCode` 只校验**格式**，不校验该代码是否对应真实存在的上市公司。

- `600000` 格式合法，对应浦发银行（存在）；
- `600999` 格式也合法，但可能没有对应公司（或对应其他公司）。

如果业务需要**存在性校验**，需要对接行情数据服务商（如 Wind、东方财富、Yahoo Finance）。

## 十、NASDAQ 与 NYSE：美股两套并行的代码体系

### 10.1 第一节的"小修正"

前文第五节用了"纽约证券交易所（NYSE）"代指美股——这是一个为了简化叙述而做的等价。在实际市场里，**美股 ≠ NYSE**：另一家独立交易所 NASDAQ 承担了相当一部分美股交易，仅用 NYSE 来描述美股是不完整的。

### 10.2 NASDAQ 简介

**NASDAQ**（National Association of Securities Dealers Automated Quotations，全美证券交易商协会自动报价系统）成立于 1971 年，是全球第一个电子化股票交易市场。它不设实体交易大厅，所有交易通过电子网络撮合——这在 1970 年代是革命性的创新。

### 10.3 两家交易所的代码规则对照

| 维度 | NYSE | NASDAQ |
|------|------|--------|
| 全称 | New York Stock Exchange | National Association of Securities Dealers Automated Quotations |
| 性质 | 主板交易所（场内） | 电子化交易所（场外转场内） |
| 上市公司风格 | 传统蓝筹、工业、消费 | 科技、成长型、生物医药 |
| 代码字符规则 | 1-5 个大写字母 | 1-5 个大写字母 |
| 类别股后缀 | `.A` / `.B`（如 `BRK.A`） | `.A` / `.B`（少见） |
| 长度风格 | 偏短（1-3 字母常见，如 `T`、`V`、`XOM`） | 偏长（4-5 字母常见，如 `AAPL`、`MSFT`、`GOOGL`） |
| 上市要求 | 财务门槛高 | 财务门槛低（一二层） |

### 10.4 关键认知：代码规则完全相同

尽管两家交易所在历史、定位、风格上截然不同，**股票代码的字符规则是一致的**——都是 1-5 个大写字母 + 可选的 `.X` 后缀：

```regex
^[A-Z]{1,5}(\.[A-Z])?$
```

这意味着：

- **格式校验无法区分 NYSE 和 NASDAQ**——`AAPL` 既可能是 NYSE 上市，也可能是 NASDAQ；
- **代码本身是跨交易所的**——一只股票从 NASDAQ 转板到 NYSE，代码通常保持不变（除非有重复）；
- **业务层区分**需要对接行情数据源（Bloomberg / FactSet / IEX），不是格式校验的职责。

### 10.5 ValidX 的应对

由于 NYSE 和 NASDAQ 的代码规则一致，ValidX 的 `@StockCode` 注解**用一个枚举（`Exchange.NEW_YORK`）代指"美股"**——这个简化在格式校验层面是合理的：

```java
// 仅做格式校验：美股代码（NYSE + NASDAQ 都覆盖）
@StockCode(exchanges = { StockCode.Exchange.NEW_YORK })
private String usStockCode;

// 如果需要精确区分，需在业务层调行情接口做存在性 + 交易所反查
```

> **建议**：如果你的项目有强需求区分"NYSE 上市 / NASDAQ 上市"，建议在 `StockCode.Exchange` 中新增 `NASDAQ` 枚举值（与 `NEW_YORK` 共用同一正则），业务层据此反查交易所。这不影响 ValidX 的格式校验能力，只是为业务层提供语义化的标签。

## 十一、北京证券交易所（BSE）：2021 新设，A股第三极

### 11.1 新交易所的诞生

**北京证券交易所**（Beijing Stock Exchange，BSE）于 2021 年 9 月 3 日宣布注册成立，2021 年 11 月 15 日正式开市。它的定位是**服务创新型中小企业**，与上交所（服务大型企业）、深交所（服务中型及创业板）形成"三足鼎立"。

BSE 的上市公司主要来源：

- **新三板精选层**的 71 家公司整体平移（成为首批北交所上市公司）；
- 后续从新三板创新层**升板**而来的公司；
- 少量新申请上市的公司。

### 11.2 BSE 代码规则

| 维度 | 北交所 |
|------|--------|
| 长度 | 6 位数字 |
| 字符类型 | 纯数字 |
| 开头 | 以 `8` 开头为主（`830xxx` - `839xxx`、`870xxx` - `879xxx`），2024 年起新增 `920xxx` 段 |
| 示例 | `830799`（艾融软件，首批）、`871245`（奥迪威） |

```regex
^8[3-7]\d{4}$        // 历史北交所代码（830-879 段）
^920\d{3}$           // 2024 年后新代码段
```

### 11.3 与深市的潜在冲突 ⚠️

**关键问题**：深市历史上有 `430xxx`、`830xxx` 等新三板代码（已退市或转板），与北交所代码**字符空间有重叠**。

实际情况：

| 代码段 | 归属 | 当前状态 |
|--------|------|---------|
| `400xxx` | 深市老三板（退市整理）| 多数已退市 |
| `430xxx` | 深市新三板（已转板）| 基本已转北交所或退市 |
| `830xxx` - `839xxx` | **北交所**（原新三板精选层平移） | 活跃 |
| `870xxx` - `879xxx` | **北交所**（后续升板） | 活跃 |
| `920xxx` | **北交所**（2024 年新段） | 活跃 |

**这意味着 ValidX 的 `^[034]\d{5}$`（深市正则）会匹配不到 `830xxx`，但 `^[034]\d{5}$` 也不能匹配 `830xxx`（开头是 8）**——所以目前**没有真正的格式冲突**。但如果业务上要严格区分"深市新三板"和"北交所"，光靠格式不够，必须做存在性 + 业务映射。

### 11.4 ValidX 现状与建议

**当前 ValidX 的 `@StockCode` 注解没有 `BSE` 枚举值**——北交所代码无法被 ValidX 识别。这不影响主流用户（大部分企业仍在沪深交易），但对北交所业务方是个明显的缺失。

**三种应对方案**：

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A. 新增 `Exchange.BEIJING` 枚举** | 一行注解搞定，最直观 | 需要修改 ValidX 源码，影响所有用户 |
| **B. 在业务层用 `@Pattern` 自定义** | 不动 ValidX 源码 | 失去 `@StockCode` 的多市场统一抽象 |
| **C. 临时方案：把北交所代码当作"特殊深市"** | 改业务层正则最小 | 业务层要做特殊判断，违背语义 |

**推荐方案 A**——给 ValidX 提个 PR：

```java
// 在 StockCode.Exchange 枚举中追加
enum Exchange {
    SHANGHAI,    // 上海证券交易所
    SHENZHEN,    // 深圳证券交易所
    HONG_KONG,   // 香港联合交易所
    NEW_YORK,    // 纽约证券交易所（NYSE + NASDAQ）
    BEIJING      // 北京证券交易所（待补）
}

// 新增正则
private static final Pattern BEIJING_PATTERN = Pattern.compile(
    "^8[3-7]\\d{4}$|^920\\d{3}$"
);
```

### 11.5 北交所业务的特殊性

相比沪深主板，北交所有一些独特的代码习惯：

- **代码段较稀疏**——目前活跃的北交所代码集中在 `830xxx` - `839xxx`、`870xxx` - `879xxx`，中间有大量未启用段；
- **新代码段不断扩展**——2024 年起开始用 `920xxx`，未来可能扩展到 `960xxx`、`980xxx`；
- **转板代码**——从北交所转板到沪深主板的股票会更换代码（原代码"退役"）。

> **实战提醒**：北交所业务对接要预留"代码段扩展"的灵活性。简单写 `^83\d{4}$` 会在 2024 年新段启用时漏掉新代码——建议用 `^8[3-9]\d{4}$|^9[2-9]\d{4}$` 这种更宽松的正则，或者干脆只校验"6 位数字 + 以 8 或 9 开头"，细节交给业务层。

## 十二、ETF / 指数 / 期权 / 权证 / 基金：衍生代码的"半壁江山"

如果你只校验股票代码，会漏掉 A 股市场一半以上的交易标的——**ETF、指数、期权、权证、基金** 这些衍生品也用 6 位数字代码，且与股票共享字符空间。

### 12.1 ETF：交易所交易基金

ETF 在沪深两市都有专属代码段：

| 市场 | 代码段 | 示例 | 说明 |
|------|--------|------|------|
| 上交所 ETF | `51xxxxx`、`56xxxxx`、`58xxxxx` | `510050`（上证 50ETF）、`510300`（沪深 300ETF） | 主流 ETF 集中在 `510xxx` |
| 上交所 LOF | `16xxxxx`、`50xxxxx` | `163406`（兴全合润）| LOF 是另一种基金形式 |
| 深交所 ETF | `15xxxxx` - `16xxxxx` | `159915`（创业板 ETF）、`159949`（创业板 50ETF）| 深市 ETF 集中在 `159xxx` |

```java
// ETF 正则（上交所 + 深交所）
private static final Pattern ETF_PATTERN = Pattern.compile(
    "^5[156]\\d{4}$" +    // 上交所 ETF（510/560/580）
    "|^1[56]\\d{4}$"      // 深交所 ETF（150-169）
);
```

> **特点**：ETF 代码与股票代码同长度（6 位）、同字符集（纯数字），但**字符空间互不重叠**——股票以 `0/3/4/6` 开头，ETF 以 `1/5` 开头，因此 `^[0156]\d{5}$` 的简单正则不会误判。

### 12.2 指数代码

指数代码在中证指数有限公司和交易所的行情系统中广泛使用：

| 指数 | 代码 | 所属 |
|------|------|------|
| 上证指数 | `000001` | 上交所 |
| 深证成指 | `399001` | 深交所 |
| 沪深 300 | `000300` | 中证 |
| 中证 500 | `000905` | 中证 |
| 创业板指 | `399006` | 深交所 |
| 科创 50 | `000688` | 上交所 |
| 北证 50 | `899050` | 北交所 |

**特征**：沪深指数用 `000xxx` / `399xxx`，**与股票代码字符空间重叠**（`000xxx` 同时是深市主板）。从格式上无法区分"深市主板股票 `000001`"和"上证指数代码 `000001`"——业务上需要根据字段语义区分。

### 12.3 期权代码

期权代码规则与股票完全不同，是**合约代码 + 标识**的组合：

#### 上交所股票期权

```
50ETF 购 9 月 2400
┌──┬──┴──┬──┴──┬───┴───┐
│  │    │     │       │
代码 合约  月份  行权价
 10000xxx + 50ETF + 2400A
```

**实际代码规则**：
- 50ETF 期权：`10000xxx`（9 位数字，前 5 位固定，后 4 位为合约序号）
- 300ETF 期权：`10001xxx` - `10003xxx`
- 中证 1000 期权：`10004xxx`+
- 沪深 300 股指期权：`IOxxxx`（字母 + 数字混合）

#### 深交所股票期权

- 沪深 300 期权：`90000xxx`
- 中证 1000 期权：`90001xxx`+
- 创业板 ETF 期权：`90002xxx`+

**期权的代码格式校验很复杂**——需要区分标的 + 月份 + 行权价 + 类型（C/P），远超简单正则能覆盖的范围。ValidX 目前不建议做期权代码校验，建议业务层单独实现。

### 12.4 港股权证与牛熊证

香港市场的衍生品代码规则：

| 类型 | 代码段 | 说明 |
|------|--------|------|
| 股本权证 | `1000` - `9999`（4 位数字）| 上市公司发行的 |
| 衍生权证 | `10000` - `99999`（5 位数字）| 投行发行的结构性产品 |
| 牛熊证 (CBBC) | `60000` - `69999`（5 位数字）| 看涨/看跌合约 |

```java
// 港股权证 + 牛熊证
private static final Pattern HK_WARRANT_PATTERN = Pattern.compile("^\\d{4,5}$");
private static final Pattern HK_CBBC_PATTERN = Pattern.compile("^6\\d{4}$");
```

**冲突点**：港股权证 `5xxxxx` 和港股主板 `5xxxxx` 字符空间重叠——`500001` 可能是腾讯的主板代码，也可能是某只权证。**业务上必须配合标的股票代码一起校验**。

### 12.5 美股 ETF 与股票代码的区别

美股 ETF 与股票共用代码规则（1-5 字母），无法从格式区分。但实际风格上有差异：

| 风格 | 股票代码 | ETF 代码 |
|------|---------|---------|
| 长度 | 1-5 字母都有 | 多数 3-4 字母 |
| 后缀 | 类别股带 `.A`/`.B` | 通常无后缀 |
| 示例 | `AAPL`、`MSFT`、`BRK.A` | `SPY`、`QQQ`、`VOO` |

**没有可校验的格式差异**——必须靠存在性接口识别。

### 12.6 衍生代码的校验策略

| 标的类型 | ValidX 是否适合校验 | 推荐方案 |
|---------|--------------------|---------|
| A 股 ETF / LOF | ✅ 适合（专属段） | 自定义 `@EtfCode` 扩展 |
| 指数代码 | ⚠️ 部分（与股票字符空间重叠）| 业务层按字段语义区分 |
| 股票期权 | ❌ 不适合 | 自定义复合校验 |
| 港股权证 / 牛熊证 | ⚠️ 部分（字符空间重叠）| 业务层配合标的股票 |
| 美股 ETF | ❌ 无法与股票区分 | 业务层识别 |

**结论**：衍生代码的校验**不能简单复用股票代码的正则**。建议：

1. **格式宽松**——`isFixedLength(code, 6)` 或 `^[0-9]{6}$` 先挡掉明显非法的；
2. **语义区分**——业务层根据上下文判断是股票、ETF、还是指数；
3. **存在性兜底**——关键场景必须对接行情接口确认标的真实性。

## 十三、国际证券识别码：ISIN / CUSIP / SEDOL

跨市场对接（沪深港通、QDII、跨境 ETF）时，股票代码不再够用——需要使用**国际证券识别码**。

### 13.1 ISIN（International Securities Identification Number）

**ISO 6166** 标准定义的全球统一证券识别码：

| 段 | 长度 | 说明 |
|----|------|------|
| 国家代码 | 2 位 | ISO 3166-1 alpha-2（如 `US`、`CN`、`HK`）|
| 标识符 | 9 位 | 国家内部编号（数字或字母）|
| 校验位 | 1 位 | Luhn 算法变体（ISO 6166 算法）|

**示例**：
- `US0378331005` —— AAPL（苹果）
- `CN0000001XH9` —— 中国国债示例
- `HK0000000002` —— 香港交易所

**正则**：`^[A-Z]{2}[A-Z0-9]{9}[0-9]$`

### 13.2 CUSIP（北美专用）

| 段 | 长度 | 说明 |
|----|------|------|
| 发行人号 | 6 位 | 字母+数字 |
| 发行号 | 2 位 | 字母+数字 |
| 校验位 | 1 位 | mod 10 加权 |

**示例**：`037833100` —— AAPL

**正则**：`^[0-9A-Z]{6}[0-9A-Z]{2}[0-9]$`

### 13.3 SEDOL（英国 / 伦敦专用）

| 段 | 长度 | 说明 |
|----|------|------|
| 标识符 | 6 位 | 字母+数字（去掉 0/O、1/I/L 等易混字符）|
| 校验位 | 1 位 | 加权 mod 10 |

**示例**：`B0YBKJ7` —— AAPL on LSE

**正则**：`^[0-9B-DF-HJ-NP-TV-Z]{6}[0-9]$`（避开 `0/O/1/I/L` 等歧义字符）

### 13.4 三种识别码的对照

| 维度 | ISIN | CUSIP | SEDOL |
|------|------|-------|-------|
| 覆盖范围 | 全球 | 美国 + 加拿大 | 英国 + 爱尔兰 |
| 长度 | 12 位 | 9 位 | 7 位 |
| 字符集 | 字母 + 数字 | 字母 + 数字 | 字母 + 数字（去歧义） |
| 校验算法 | Luhn 变体 | mod 10 加权 | mod 10 加权 |
| 主导机构 | ANNA | CUSIP Global Services | London Stock Exchange |
| 跨境对接 | ✅ 通用 | ⚠️ 仅北美 | ⚠️ 仅英国 |

### 13.5 实战中的使用场景

| 业务 | 用什么码 | 原因 |
|------|---------|------|
| 美股交易系统 | Ticker（`AAPL`）| 内部使用最简洁 |
| 美股对外接口 | CUSIP 或 ISIN | 标准化的"身份证" |
| 全球指数（MSCI、富时） | ISIN | 跨市场唯一 |
| 沪深港通北向交易 | ISIN | 跨境对接的唯一标识 |
| LSE（伦敦）交易 | SEDOL | 英国本地系统 |
| 跨境 ETF 申赎 | ISIN | 跨市场结算 |

### 13.6 ValidX 现状与建议

**当前 ValidX 不内置 ISIN/CUSIP/SEDOL 校验**。如果你的项目有跨境业务，建议扩展：

```java
// ISIN 自定义注解示例
public @interface Isin {
    String message() default "{...isin.invalid}";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

public class IsinValidator implements ConstraintValidator<Isin, String> {
    private static final Pattern ISIN_PATTERN = Pattern.compile("^[A-Z]{2}[A-Z0-9]{9}[0-9]$");
    
    @Override
    public boolean isValid(String value, ConstraintValidatorContext ctx) {
        if (value == null || value.isEmpty()) return true;
        if (!ISIN_PATTERN.matcher(value).matches()) return false;
        // ... 校验位校验（ISO 6166 算法）
        return verifyCheckDigit(value);
    }
}
```

ISO 6166 的校验位算法是 Luhn 算法的变体（数字部分展开后做 mod 10）——实现略复杂但完整可行。

## 十四、复合校验：链式 API 自定义扩展覆盖全市场

### 14.1 业务场景

当你的系统需要校验"可能是任何一种股票 / 衍生品 / 国际识别码"时，单一注解已经不够用——你需要**复合校验**。

例如：
- 行情聚合系统收到一条记录，不知道是 A 股、港股、美股还是 ISIN；
- 用户在搜索框输入任意代码，系统自动识别市场并校验；
- 跨境 ETF 系统同时处理标的 ETF 代码和底层资产识别码。

### 14.2 方案一：链式 API 自定义方法

直接用 ValidX 的链式 API 拼接：

```java
public class CompositeStockValidator {

    public static ValidationResult validate(String code) {
        ValidX v = ValidX.init().withLocale(Locale.SIMPLIFIED_CHINESE);
        String market = null;

        // 1. 美股优先（1-5 字母）
        if (v.isUpper(code).passed() && code.matches("^[A-Z]{1,5}(\\.[A-Z])?$")) {
            market = "US";
        }
        // 2. A 股（6 位数字）
        else if (v.isFixedLength(code, 6).passed()) {
            if (v.field("代码").isStockCode(code, 
                    StockCode.Exchange.SHANGHAI, 
                    StockCode.Exchange.SHENZHEN).passed()) {
                market = "A";
            }
        }
        // 3. 港股（4-5 位数字）
        else if (v.isStockCode(code, StockCode.Exchange.HONG_KONG).passed()) {
            market = "HK";
        }
        // 4. ISIN（12 位）
        else if (code.matches("^[A-Z]{2}[A-Z0-9]{9}[0-9]$")) {
            market = "ISIN";
        }

        return new ValidationResult(market, v.getErrors());
    }

    @Data
    @AllArgsConstructor
    public static class ValidationResult {
        private String market;
        private List<String> errors;
        public boolean passed() { return market != null && errors.isEmpty(); }
    }
}
```

### 14.3 方案二：自定义复合注解 `@CompositeStockCode`

更高阶的做法是封装成自己的注解：

```java
@Target({ElementType.METHOD, ElementType.FIELD})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = CompositeStockCodeValidator.class)
public @interface CompositeStockCode {
    String message() default "{...composite.stock.code.invalid}";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};

    /** 允许的市场类型，默认全开 */
    CompositeStockMarket[] markets() default {
        CompositeStockMarket.SHANGHAI,
        CompositeStockMarket.SHENZHEN,
        CompositeStockMarket.BEIJING,    // 待 ValidX 支持
        CompositeStockMarket.HONG_KONG,
        CompositeStockMarket.NEW_YORK,    // 含 NASDAQ
        CompositeStockMarket.ISIN
    };

    enum CompositeStockMarket {
        SHANGHAI, SHENZHEN, BEIJING, HONG_KONG, NEW_YORK, ISIN
    }
}

public class CompositeStockCodeValidator 
        implements ConstraintValidator<CompositeStockCode, String> {

    private Set<CompositeStockMarket> markets;

    @Override
    public void initialize(CompositeStockCode anno) {
        this.markets = new HashSet<>(Arrays.asList(anno.markets()));
    }

    @Override
    public boolean isValid(String value, ConstraintValidatorContext ctx) {
        if (value == null || value.isEmpty()) return true;

        // 美股（NYSE + NASDAQ 共用规则）
        if (markets.contains(CompositeStockMarket.NEW_YORK)) {
            if (value.matches("^[A-Z]{1,5}(\\.[A-Z])?$")) return true;
        }
        // 港股
        if (markets.contains(CompositeStockMarket.HONG_KONG)) {
            if (value.matches("^\\d{4,5}$")) return true;
        }
        // A 股（沪深）
        if (markets.contains(CompositeStockMarket.SHANGHAI)
                || markets.contains(CompositeStockMarket.SHENZHEN)) {
            if (value.matches("^[0346]\\d{5}$")) return true;
        }
        // 北交所（假设已支持）
        if (markets.contains(CompositeStockMarket.BEIJING)) {
            if (value.matches("^8[3-7]\\d{4}$|^920\\d{3}$")) return true;
        }
        // ISIN
        if (markets.contains(CompositeStockMarket.ISIN)) {
            if (value.matches("^[A-Z]{2}[A-Z0-9]{9}[0-9]$")) {
                return isinCheckDigit(value); // ISO 6166 算法
            }
        }
        return false;
    }

    private boolean isinCheckDigit(String isin) {
        // ISO 6166 校验位算法（略）
        // 1. 将字母展开为数字（A=10, B=11, ..., Z=35）
        // 2. 从右向左，奇数位 × 2（如 > 9 则 - 9）
        // 3. 求和，检查 mod 10 == 0
        return true; // 占位
    }
}
```

### 14.4 复合校验的最佳实践

| 场景 | 推荐方案 |
|------|---------|
| 单市场校验（如"只接受 A 股"）| 直接用 `@StockCode(exchanges = {SHANGHAI, SHENZHEN})` |
| 双市场并列（如"沪深 + 港股"）| `@StockCode(exchanges = {SHANGHAI, SHENZHEN, HONG_KONG})` |
| 全市场 + 国际码 | 自定义 `@CompositeStockCode` |
| 美股 NYSE vs NASDAQ 区分 | 业务层调行情接口 |
| 存在性 + 交易所识别 | 业务层 + 行情数据源 |

**取舍**：

- 复合校验的**灵活性**换来了**复杂度**——正则之间的优先级、字符空间的重叠、错误消息的统一都是难题；
- 对绝大多数业务，**ValidX 内置的 `@StockCode` 已经够用**——只在确实需要覆盖全市场时才考虑自定义复合注解；
- **永远不要把"业务判断"放进校验器**——校验器只判格式，市场归属、ETF/股票区分应该交给业务层。

### 14.5 一个完整的示例：行情聚合系统

```java
@Service
public class TickerAggregatorService {

    public AggregatedQuote aggregate(String inputCode) {
        CompositeStockValidator.ValidationResult v = 
                CompositeStockValidator.validate(inputCode);

        if (!v.passed()) {
            throw new BusinessException("代码格式错误：" + v.getErrors());
        }

        // 根据识别出的市场调对应行情源
        return switch (v.getMarket()) {
            case "A"  -> eastMoneyClient.query(inputCode);  // 东方财富
            case "HK" -> hkexClient.query(inputCode);       // 港交所行情
            case "US" -> iexClient.query(toTicker(inputCode)); // IEX
            case "ISIN" -> refinitivClient.query(inputCode); // Refinitiv ISIN 索引
            default -> throw new IllegalStateException("未知市场: " + v.getMarket());
        };
    }
}
```

## 总结

股票代码校验看似简单，但四个交易所的规则差异足以让人踩坑。本文把沪深港美四大市场的代码规则梳理清楚，并配合 ValidX 的 `@StockCode` 注解，实现了"一行代码搞定多市场校验"。

**核心知识点回顾**：

| 交易所 | 代码规则 | 正则 | ValidX 枚举 |
|--------|---------|------|------------|
| 上海证券交易所 | 6位数字，以 `6` 开头 | `^6\d{5}$` | `Exchange.SHANGHAI` |
| 深圳证券交易所 | 6位数字，以 `0`、`3`、`4` 开头 | `^[034]\d{5}$` | `Exchange.SHENZHEN` |
| 香港联合交易所 | 4-5位数字 | `^\d{4,5}$` | `Exchange.HONG_KONG` |
| 纽约证券交易所 | 1-5位字母，可带点号 | `^[A-Z]{1,5}(\.[A-Z])?$` | `Exchange.NEW_YORK` |

**业务实战建议**：

1. **用户选择市场时**：用 `exchanges` 参数精确校验，避免误匹配；
2. **用户未选择市场时**：用默认的"全市场"模式自动识别；
3. **港股注意前导零**：业务层统一格式化（补零或去零）；
4. **美股注意大小写**：虽然校验不敏感，但展示时统一大写；
5. **格式校验后接存在性校验**：用 `@StockCode` 挡格式，用外部 API 验证存在性。

```java
// 最简用法：一行注解
@StockCode(message = "股票代码格式不正确")
private String stockCode;

// 最灵活用法：链式 API 指定交易所
ValidX.init()
     .field("股票代码")
     .isStockCode(code, StockCode.Exchange.SHANGHAI);
```
