# 退款申请验证：订单状态、退款金额、原因校验

## 引言

在电商和支付系统中，退款是用户最核心的售后诉求之一。然而，看似简单的"用户申请退款"背后，涉及着极其复杂的业务校验逻辑：

- 订单必须是**已支付**状态才能发起退款
- 退款金额**不能超过订单实付金额**
- 退款原因必须在**预设白名单**内
- 同一笔订单**不能重复申请**退款
- 超过**7天/15天/30天**的订单可能无法退款
- 部分商品（如虚拟商品、生鲜）**不支持退款**

如果这些校验出现漏洞，轻则用户体验受损，重则导致资金损失。本文以一个真实的电商退款场景为例，讲解如何用 ValidX 从 DTO 到 Service 层建立完整的退款申请验证体系。

---

## 一、退款申请的业务场景分析

### 1.1 退款流程概述

```
用户发起退款申请
    ↓
校验退款资格（订单状态、时效、商品类型）
    ↓
校验退款金额（部分退款 / 全额退款）
    ↓
校验退款原因（必填 / 白名单 / 其他需补充）
    ↓
生成退款单 → 进入审批 / 自动退款流程
```

### 1.2 退款类型

| 退款类型 | 说明 | 金额规则 |
|---------|------|---------|
| **全额退款** | 整单退货退款 | 退款金额 = 订单实付金额 |
| **部分退款** | 部分商品退货退款 | 退款金额 ≤ 对应商品实付金额 |
| **仅退款** | 无需退货（如未发货） | 退款金额 = 订单实付金额 |
| **退差价** | 价格保护 | 退款金额 = 差价 |

### 1.3 常见退款陷阱

| 陷阱 | 场景 | 后果 |
|------|------|------|
| 重复退款 | 用户多次点击提交，系统未做幂等 | 同一订单退款多次，资金损失 |
| 超额退款 | 退款金额大于订单实付金额 | 平台多退用户钱 |
| 状态不一致 | 退款时订单已被取消或完成 | 退款到已完成订单，逻辑矛盾 |
| 时效漏洞 | 超过退款期限仍可申请 | 售后政策形同虚设 |
| 原因缺失 | 退款原因未填写或不在白名单 | 无法统计分析，合规风险 |

## 三、核心验证规则实现

### 3.1 订单状态校验

订单状态是退款的第一道门槛，只有特定状态的订单才能发起退款：

```java
@Service
public class RefundService {

    @Autowired
    private OrderRepository orderRepository;

    /**
     * 校验订单是否允许退款
     */
    public void validateOrderForRefund(String orderNo) {
        Order order = orderRepository.findByOrderNo(orderNo);

        ValidX chain = ValidX.init()
                .withLocale(Locale.SIMPLIFIED_CHINESE);

        // 规则 1：订单必须存在
        if (order == null) {
            chain.field("订单号").fail("订单不存在");
            throw new RefundException(chain.getErrors());
        }

        // 规则 2：订单状态必须是"已支付"或"已发货"
        if (!Arrays.asList(OrderStatus.PAID, OrderStatus.SHIPPED).contains(order.getStatus())) {
            chain.field("订单状态")
                 .fail("当前订单状态为" + order.getStatusName() + "，不允许发起退款");
        }

        // 规则 3：订单未超过退款时效（如 7 天）
        if (order.isExpiredForRefund()) {
            chain.field("退款时效")
                 .fail("订单已超过退款有效期（" + order.getRefundDeadline() + "），无法退款");
        }

        // 规则 4：订单未处于退款中
        if (order.hasOngoingRefund()) {
            chain.field("退款状态").fail("该订单已有进行中的退款申请，不能重复提交");
        }

        if (!chain.passed()) {
            throw new RefundException(chain.getErrors());
        }
    }
}
```

### 3.2 退款金额校验

退款金额是退款校验的核心，涉及金额上限、精度、货币等多个维度：

```java
@Service
public class RefundAmountValidator {

    @Autowired
    private OrderRepository orderRepository;

    /**
     * 校验退款金额的合法性
     */
    public void validateRefundAmount(String orderNo, Long refundAmount, 
                                     List<RefundItemDTO> refundItems, 
                                     RefundType refundType) {
        Order order = orderRepository.findByOrderNo(orderNo);
        ValidX chain = ValidX.init().withLocale(Locale.SIMPLIFIED_CHINESE);

        // 规则 1：退款金额必须大于 0
        chain.field("退款金额").notNull().isGreaterThan(refundAmount, 0L);

        // 规则 2：退款金额不能超过订单实付金额
        Long paidAmount = order.getPaidAmount();
        if (refundAmount > paidAmount) {
            chain.field("退款金额").fail(
                String.format("退款金额（%.2f 元）不能超过订单实付金额（%.2f 元）",
                    refundAmount / 100.0, paidAmount / 100.0));
        }

        // 规则 3：已退款总额 + 本次退款金额 ≤ 订单实付金额
        Long totalRefunded = order.getTotalRefundedAmount();
        if (totalRefunded + refundAmount > paidAmount) {
            chain.field("退款金额").fail(
                String.format("累计退款金额（%.2f 元）不能超过订单实付金额（%.2f 元），" +
                    "已退款 %.2f 元，本次最多可退 %.2f 元",
                    (totalRefunded + refundAmount) / 100.0, 
                    paidAmount / 100.0,
                    totalRefunded / 100.0,
                    (paidAmount - totalRefunded) / 100.0));
        }

        // 规则 4：退款金额精度校验（分位，不能有小数）
        if (refundAmount % 1 != 0) {
            chain.field("退款金额").fail("退款金额必须为整数分，不能包含小数");
        }

        // 规则 5：部分退款时，退款金额必须与商品项匹配
        if (refundType == RefundType.PARTIAL && (refundItems == null || refundItems.isEmpty())) {
            chain.field("退款商品").fail("部分退款时必须指定退款商品");
        }

        // 规则 6：部分退款时，逐项校验商品退款数量
        if (refundType == RefundType.PARTIAL && refundItems != null) {
            Long calculatedAmount = 0L;
            for (int i = 0; i < refundItems.size(); i++) {
                RefundItemDTO item = refundItems.get(i);
                OrderItem orderItem = order.getItemById(item.getOrderItemId());

                if (orderItem == null) {
                    chain.field("退款商品[" + i + "]").fail("商品项不存在于订单中");
                    continue;
                }

                // 退款数量不能大于购买数量
                if (item.getRefundQuantity() > orderItem.getQuantity()) {
                    chain.field("退款商品[" + i + "]").fail(
                        String.format("退款数量（%d）不能大于购买数量（%d）",
                            item.getRefundQuantity(), orderItem.getQuantity()));
                }

                // 累计退款数量不能大于购买数量
                int alreadyRefunded = orderItem.getRefundedQuantity();
                if (alreadyRefunded + item.getRefundQuantity() > orderItem.getQuantity()) {
                    chain.field("退款商品[" + i + "]").fail(
                        String.format("累计退款数量（%d）不能大于购买数量（%d），" +
                            "已退款 %d 件，本次最多可退 %d 件",
                            alreadyRefunded + item.getRefundQuantity(),
                            orderItem.getQuantity(),
                            alreadyRefunded,
                            orderItem.getQuantity() - alreadyRefunded));
                }

                calculatedAmount += item.getRefundQuantity() * item.getUnitPrice();
            }

            // 退款金额与商品计算金额匹配（允许误差 1 分，四舍五入差异）
            if (Math.abs(calculatedAmount - refundAmount) > 1) {
                chain.field("退款金额").fail(
                    String.format("退款金额（%.2f 元）与商品计算金额（%.2f 元）不一致",
                        refundAmount / 100.0, calculatedAmount / 100.0));
            }
        }

        if (!chain.passed()) {
            throw new RefundException(chain.getErrors());
        }
    }
}
```

### 3.3 退款原因校验

退款原因不仅是必填项，还需要在白名单内，特定原因可能需要补充说明：

```java
@Service
public class RefundReasonValidator {

    // 退款原因白名单（编码 -> 是否需要补充说明）
    private static final Map<String, Boolean> REASON_WHITELIST = new HashMap<>() {{
        put("QUALITY_ISSUE", false);        // 商品质量问题
        put("WRONG_ITEM", false);            // 发错货/少发货
        put("DAMAGED", false);               // 商品损坏
        put("NOT_AS_DESCRIBED", false);     // 与描述不符
        put("DONT_WANT", false);             // 不想要了
        put("WRONG_SIZE", false);            // 尺码不合适
        put("SHIPPING_DELAY", false);        // 物流延迟
        put("OTHER", true);                  // 其他原因（需补充说明）
    }};

    /**
     * 校验退款原因
     */
    public void validateRefundReason(String reasonCode, String reasonDesc) {
        ValidX chain = ValidX.init().withLocale(Locale.SIMPLIFIED_CHINESE);

        // 规则 1：退款原因必须在白名单内
        if (!REASON_WHITELIST.containsKey(reasonCode)) {
            chain.field("退款原因").fail("退款原因不合法，请选择有效的退款原因");
            throw new RefundException(chain.getErrors());
        }

        // 规则 2：特定原因需要补充说明
        Boolean needsDesc = REASON_WHITELIST.get(reasonCode);
        if (Boolean.TRUE.equals(needsDesc) && 
            (reasonDesc == null || reasonDesc.trim().isEmpty())) {
            chain.field("补充说明").fail("选择"其他"原因时，必须填写补充说明");
        }

        // 规则 3：补充说明长度校验
        if (reasonDesc != null && reasonDesc.length() > 500) {
            chain.field("补充说明").fail("补充说明不能超过 500 字");
        }

        // 规则 4：补充说明不能包含敏感词
        if (reasonDesc != null && containsSensitiveWords(reasonDesc)) {
            chain.field("补充说明").fail("补充说明包含敏感内容，请修改后重试");
        }

        if (!chain.passed()) {
            throw new RefundException(chain.getErrors());
        }
    }

    private boolean containsSensitiveWords(String text) {
        // 敏感词检测逻辑（可接入第三方敏感词库）
        return false;
    }
}
```

## 四、完整的退款申请 Service

### 4.1 退款申请入口

```java
@Service
@RequiredArgsConstructor
public class RefundApplicationService {

    private final OrderRepository orderRepository;
    private final RefundRepository refundRepository;
    private final RefundAmountValidator amountValidator;
    private final RefundReasonValidator reasonValidator;

    /**
     * 提交退款申请
     */
    @Transactional
    public RefundResult applyRefund(@Valid RefundApplyRequest request) {
        String orderNo = request.getOrderNo();
        Order order = orderRepository.findByOrderNo(orderNo);

        // ========== Step 1: 订单状态校验 ==========
        ValidX orderChain = ValidX.init().withLocale(Locale.SIMPLIFIED_CHINESE);

        if (order == null) {
            orderChain.field("订单号").fail("订单不存在");
            throw new RefundException(orderChain.getErrors());
        }

        // 状态校验
        if (!order.canRefund()) {
            orderChain.field("订单状态").fail(
                String.format("当前订单状态为【%s】，不允许退款", order.getStatusName()));
        }

        // 时效校验
        if (order.isExpiredForRefund()) {
            orderChain.field("退款时效").fail(
                String.format("订单已超过退款有效期（%s），无法退款", order.getRefundDeadline()));
        }

        // 幂等校验：是否已有进行中的退款
        if (order.hasOngoingRefund()) {
            orderChain.field("退款状态").fail("该订单已有进行中的退款申请");
        }

        if (!orderChain.passed()) {
            throw new RefundException(orderChain.getErrors());
        }

        // ========== Step 2: 退款金额校验 ==========
        amountValidator.validateRefundAmount(
            orderNo, 
            request.getRefundAmount(),
            request.getRefundItems(),
            RefundType.of(request.getRefundType())
        );

        // ========== Step 3: 退款原因校验 ==========
        reasonValidator.validateRefundReason(
            request.getRefundReasonCode(),
            request.getRefundReasonDesc()
        );

        // ========== Step 4: 生成退款单 ==========
        RefundOrder refundOrder = RefundOrder.create(
            order,
            RefundType.of(request.getRefundType()),
            request.getRefundAmount(),
            request.getRefundReasonCode(),
            request.getRefundReasonDesc(),
            request.getRefundItems()
        );

        refundRepository.save(refundOrder);

        // ========== Step 5: 发送退款申请事件 ==========
        eventPublisher.publishEvent(new RefundAppliedEvent(refundOrder));

        return RefundResult.success(refundOrder.getRefundNo());
    }
}
```

### 4.2 退款单实体

```java
@Entity
public class RefundOrder {

    @Id
    private String refundNo;              // 退款单号
    private String orderNo;               // 原订单号
    private String refundType;            // 退款类型
    private Long refundAmount;            // 退款金额（分）
    private String refundReasonCode;      // 退款原因编码
    private String refundReasonDesc;      // 退款原因补充
    private RefundStatus status;          // 退款状态
    private LocalDateTime createdAt;      // 创建时间

    @OneToMany(cascade = CascadeType.ALL)
    private List<RefundOrderItem> items;  // 退款商品项

    /**
     * 工厂方法：创建退款单
     */
    public static RefundOrder create(Order order, RefundType type, Long amount,
                                     String reasonCode, String reasonDesc,
                                     List<RefundItemDTO> itemDTOs) {
        RefundOrder refund = new RefundOrder();
        refund.refundNo = generateRefundNo();
        refund.orderNo = order.getOrderNo();
        refund.refundType = type.getCode();
        refund.refundAmount = amount;
        refund.refundReasonCode = reasonCode;
        refund.refundReasonDesc = reasonDesc;
        refund.status = RefundStatus.PENDING;
        refund.createdAt = LocalDateTime.now();

        // 构建退款商品项
        if (itemDTOs != null) {
            refund.items = itemDTOs.stream()
                .map(dto -> RefundOrderItem.of(dto, order))
                .collect(Collectors.toList());
        }

        return refund;
    }

    private static String generateRefundNo() {
        return "RF" + LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyyMMddHHmmss"))
               + String.format("%06d", new Random().nextInt(1000000));
    }
}
```

## 五、全局异常处理

```java
@RestControllerAdvice
public class RefundExceptionHandler {

    @ExceptionHandler(RefundException.class)
    public ResponseEntity<ErrorResponse> handleRefundException(RefundException e) {
        return ResponseEntity.badRequest()
            .body(new ErrorResponse(400, "退款申请失败", e.getErrors()));
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidation(MethodArgumentNotValidException e) {
        List<String> errors = e.getBindingResult()
            .getFieldErrors()
            .stream()
            .map(f -> f.getField() + ": " + f.getDefaultMessage())
            .collect(Collectors.toList());

        return ResponseEntity.badRequest()
            .body(new ErrorResponse(400, "请求参数错误", errors));
    }
}
```

## 六、常见坑与规避方案

### 6.1 重复退款（幂等性）

**问题**：用户快速点击多次"提交退款"，系统未做幂等处理。

**解决方案**：

```java
// 方案 1：数据库唯一索引（推荐）
// CREATE UNIQUE INDEX idx_order_refunding ON refund_order(order_no) WHERE status = 'PENDING';

// 方案 2：分布式锁
@Service
public class RefundApplicationService {

    @Autowired
    private StringRedisTemplate redisTemplate;

    public RefundResult applyRefund(RefundApplyRequest request) {
        String lockKey = "refund:lock:" + request.getOrderNo();
        Boolean locked = redisTemplate.opsForValue()
            .setIfAbsent(lockKey, "1", Duration.ofSeconds(10));

        if (!Boolean.TRUE.equals(locked)) {
            throw new RefundException(List.of("退款申请正在处理中，请勿重复提交"));
        }

        try {
            // 执行退款逻辑
            return doApplyRefund(request);
        } finally {
            redisTemplate.delete(lockKey);
        }
    }
}
```

### 6.2 并发退款金额超支

**问题**：两个退款申请同时处理，各自校验通过，但累计退款金额超过订单实付。

**解决方案**：

```java
// 方案：数据库乐观锁
@Entity
public class Order {
    @Version
    private Integer version;  // 乐观锁版本号
}

// 退款时更新订单的已退款金额，利用 @Version 防止并发冲突
@Modifying
@Query("UPDATE Order o SET o.totalRefundedAmount = o.totalRefundedAmount + :amount, " +
       "o.version = o.version + 1 " +
       "WHERE o.orderNo = :orderNo AND o.version = :version")
int updateRefundedAmount(@Param("orderNo") String orderNo, 
                         @Param("amount") Long amount,
                         @Param("version") Integer version);
```

### 6.3 退款金额精度丢失

**问题**：金额用 `double` 计算导致精度丢失。

**解决方案**：

```java
// ❌ 错误：double 计算
Double refundAmount = order.getPaidAmount() * 0.1;  // 精度丢失

// ✅ 正确：使用 BigDecimal 或长整型（分）
Long refundAmount = order.getPaidAmount() / 10;       // 精确计算
```

## 七、总结

退款申请看似简单的业务，实则涉及**状态机、金额计算、时效控制、并发安全**等多个技术难点。ValidX 的链式 API 为退款校验提供了清晰的验证流程编排能力，配合注解在 DTO 层的格式校验，可以构建起完整的退款申请验证体系。

| 校验维度 | 核心规则 | ValidX 工具 |
|---------|---------|-----------|
| 订单状态 | 已支付/已发货、未过期、无进行中的退款 | 链式 API（`isIn`、`fail`） |
| 退款金额 | 大于 0、不超过实付金额、精度正确 | 链式 API（`isGreaterThan`） |
| 退款原因 | 白名单内、特定原因需补充说明 | 链式 API（`isIn` + 自定义逻辑） |
| 并发安全 | 分布式锁 + 乐观锁 | 数据库 + Redis |
| 幂等性 | 同一订单不能重复退款 | 唯一索引 + 分布式锁 |

通过 ValidX 的分层校验，可以确保退款申请在**入口处拦截非法请求**、**业务层保证金额安全**、**持久化层防止并发冲突**，最终实现安全、可靠的退款流程。
