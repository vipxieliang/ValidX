# 外国人永久居留身份证（五星卡）详解

## 前言

提到"中国绿卡"，很多人会想到影视剧里外国人在中国畅行无阻的潇洒形象，但现实中它是一张极难拿到、又极具分量的证件——**《中华人民共和国外国人永久居留身份证》**。2023 年 12 月新版启用后，它因为背面的五星防伪设计被亲切地称为"**五星卡**"。

这张证件和居民身份证看起来很像：都是 18 位号码、都嵌了芯片、都能用身份证读卡机读取。但它**不是居民身份证**：持证人没有中国国籍、没有户籍、号码也不是行政区划代码开头。对开发者来说，最关心的问题只有一个：

> 18 位号码里到底藏着什么？和居民身份证的 18 位有什么区别？能不能用同一个校验器去验证？

今天这篇文章，我们从历史沿革讲到证件式样，重点拆解**18 位号码的编码规则**，最后结合 **ValidX** 给出"五星卡"与居民身份证的校验分工方案。

## 一、什么是外国人永久居留身份证

### 定义

它是**获得在中国永久居留资格的外国人在中国境内居留的合法身份证件**，可以单独使用，办理金融、教育、医疗、交通、住宿、通信、工作、税收和社会保险、财产登记、诉讼等事务时无需再携带护照。

三个关键词：

- **居留资格**：居留期限不受限制，不等于入籍，持证人仍保留原国籍
- **身份证件**：与护照搭配使用，是"身份认证"而非"出入境通行证"（出入境仍凭有效护照）
- **外国人标识**：号码首位 `9`，与我国公民身份号码首位 `1~8` 严格区分

### 它与居民身份证的本质区别

| 维度 | 居民身份证 | 外国人永久居留身份证 |
|------|-----------|---------------------|
| 面向人群 | 中国公民 | 取得永久居留资格的外国人 |
| 法律性质 | 公民身份证明 | 居留资格证明 |
| 号码开头 | 行政区划代码（首位 `1~8`） | 外国人标识码 `9` |
| 号码位数 | 18 位（含 15 位老版） | 2004 版 15 位 → 2023 版 18 位 |
| 出入境凭证 | 部分口岸可用 | 不行，须凭有效护照 |
| 发证机关 | 县级以上公安机关 | 国家移民管理局 |

## 二、历史沿革：从"绿卡"到"五星卡"

### 1. 改革开放初期（1986）

1986 年施行的《中华人民共和国外国人入境出境管理法》首次在法律层面规定了外国人在中国可获**长期居留或永久居留资格**。这一时期尚没有统一证件。

### 2. 2004 年版永居证（"中国绿卡"）

2004 年 8 月，公安部、外交部发布第 74 号令《外国人在中国永久居留审批管理办法》，正式实施永久居留证制度，开始签发《中华人民共和国外国人永久居留证》，俗称"中国绿卡"。**该版采用 15 位证件号码**。

签发量极低：2004 至 2013 年十年间全国仅签发 7,356 张，被外界批评"门槛太高"。

### 3. 2017 年版永居身份证

2017 年 6 月，公安部开始签发《中华人民共和国外国人永久居留身份证》——名称中加入"身份"二字，**强化身份认证功能**；参照第二代居民身份证标准重新设计，内嵌非接触式芯片，可用身份证阅读机具读取。但**号码仍沿用 2004 版 15 位编码规则**。

2020 年《外国人永久居留管理条例（征求意见稿）》因引发争议被撤回；2022 年起国家移民管理局放宽了外籍博士等高层次人才的申请条件。

### 4. 2023 年版五星卡

2023 年 9 月 15 日，国家移民管理局宣布 12 月 1 日起签发启用新版永居证；12 月 1 日当天，首批 50 名外国人领到新版证件。新版因背面防伪设计参考五星红旗五颗星样式而得名"**五星卡**"。

**号码从 15 位升级为 18 位**，这是本文的核心——后面专门拆解。

## 三、证件式样

### 正面登载信息

- 证件名称（中英文）："中华人民共和国 / 外国人永久居留身份证 / Foreign Permanent Resident ID Card"
- 证件说明：可在金融、教育、医疗、交通、住宿、通信、工作、税收和社会保险、财产登记、诉讼等事务时**单独使用**
- 换证提示：持证人曾持有的旧号码
- 签发机关：**中华人民共和国国家移民管理局签发**（Issued by National Immigration Administration, PRC）

### 背面登载信息

- 持证人照片
- **姓名**：拉丁字符姓在前、名在后，姓与名之间用 `,` 分隔；有中文姓名时列第二行
- **性别**：`男/M` 或 `女/F`
- **出生日期**：`YYYY.MM.DD`
- **国籍**：持证人国籍国中文名简称 + ISO 3166-1 三位国家代码
- **有效期限**：`20YY.MM.DD - 20YY.MM.DD`，**有效期一般十年**（未满 18 周岁者为五年）
- **证件号码（ID No.）**：18 位

## 四、18 位号码编码规则（重点）

2023 版五星卡采用 18 位证件号码，**和公民身份号码相仿但不完全相同**。逐位拆解如下：

| 位数 | 含义 | 说明 |
|:----:|------|------|
| 第 1 位 | **外国人标识码** | 固定为 `9`，是区分中外人员、识别证件类型的依据 |
| 第 2~3 位 | **申领地代码** | 证件申领地的省级行政区划代码（如北京 `11`） |
| 第 4~6 位 | **国籍国代码** | 持证人国籍国的 ISO 3166-1 **数字代码**（如加拿大 `124`） |
| 第 7~14 位 | **出生日期码** | 格式 `YYYYMMDD`，与居民身份证位置**恰好一致** |
| 第 15~17 位 | **顺序码** | 与公民身份号码相同的编排规则 |
| 第 18 位 | **校验码** | 与公民身份号码相同的加权模 11 算法 |

> 注意：维基百科对"其余部分与公民身份号码相同"的表述，加上下面这个官方口径的示例，可以验证：出生日期在第 7~14 位、顺序码 3 位、校验码 1 位，全部与居民身份证共用同一套算法。

### 官方示例拆解

维基百科给出一个完整示例：某女性、国籍国加拿大（国家地区代码 `124`）、出生于 1981 年 8 月 3 日、在北京申领（省级代码 `11`）、顺序码 `002`、校验码 `4`，完整号码为：

```
9  1 1     1 2 4   19810803  002    4
│  │─│     │───│   │──────│  │─│    │
│  申领地   国籍国   出生日期   顺序码  校验码
│  (北京)  (加拿大)
│
外国人标识码
```

逐位核对：

- 第 1 位 `9` = 外国人标识码 ✓
- 第 2~3 位 `11` = 北京（申领地省级代码）✓
- 第 4~6 位 `124` = 加拿大（ISO 3166-1 数字代码）✓
- 第 7~14 位 `19810803` = 出生日期 ✓
- 第 15~17 位 `002` = 顺序码 ✓
- 第 18 位 `4` = 校验码 ✓

### 校验码验证

我们用居民身份证同一套算法验证这个号码：前 17 位 `91112419810803002` 依次乘权重 `{7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2}` 求和：

```
9×7+1×9+1×10+1×5+2×8+4×4+1×2+9×1+8×6+1×3+0×7+8×9+0×10+3×5+0×8+0×4+2×2
= 63+9+10+5+16+16+2+9+48+3+0+72+0+15+0+0+4
= 272
```

`272 mod 11 = 8`，余数 8 对应校验码表 `{'1','0','X','9','8','7','6','5','4','3','2'}` 的第 8 个 = `4`，与示例末位一致 ✓。

这说明**五星卡的校验码与居民身份证完全同源**，这是它能被 ValidX 的加权校验器直接复用的关键。

## 五、与居民身份证的三大关键差异

### 1. 前 6 位不是行政区划代码

居民身份证前 6 位是完整的县区级地址码，可映射省份、城市、区县；五星卡**前 6 位混编了三类信息**（标识码 + 申领地 + 国籍国），**不能**用 `substring(0, 2)` 直接当省份代码。

### 2. 性别奇偶规则不能跨证件套用

居民身份证倒数第二位奇偶定性别。五星卡的顺序码虽"与公民身份号码相同"（示例中 `002` 为女性），但**维基百科仅给出单个示例，未明确公开性别奇偶规则**。生产环境**不要**用奇偶去推断五星卡持证人性别——官方未公开，仅凭一个样本下结论是危险的。

### 3. 申领地 ≠ 国籍国 ≠ 现居地

- 第 2~3 位是**申领地**（在哪申的），不是户籍（外国人也无户籍概念）
- 第 4~6 位是**国籍国**，反映持证人的外国国籍，不是居住地
- 申领后证件信息基本固定，不代表持证人的实时居留状态

## 六、申领条件与有效期

### 申领条件

依据《外国人在中国永久居留审批管理办法》第六条，申请者应遵守中国法律、身体健康、无犯罪记录，并符合下列条件之一：

1. 在中国直接投资、连续三年投资稳定且纳税记录良好
2. 担任副总经理、副厂长等以上职务，或副教授、副研究员等副高级以上职称，连续任职满四年、四年内在华居留累计不少于三年且纳税良好
3. 对中国有重大突出贡献或国家特别需要
4. 前三类人员的配偶及其未满 18 周岁未婚子女
5. 中国公民或在华永居外国人的配偶，婚姻存续满五年、已连续在华居留满五年、每年居留不少于九个月且有稳定生活保障和住所
6. 未满 18 周岁未婚子女投靠父母
7. 年满 60 周岁、在境外无直系亲属，投靠境内直系亲属，已连续在华居留满五年、每年居留不少于九个月且有稳定生活保障和住所

### 居留义务

- 获准永居者**每年在华累计居留不得少于三个月**；确需出境的，经批准可在五年内累计居留不少于一年

### 有效期

- 未满 18 周岁：**五年**
- 18 周岁及以上：**十年**

## 七、结合 ValidX 的校验实践

### 核心原则：按证件类型分发，切勿混用

五星卡和居民身份证虽然号码长度、日期位置、校验算法相同，但**首位不同、前 6 位语义不同、性别规则不可靠**，所以**必须用两套校验器分别把关**，不能共用一个正则。

ValidX 已内置完整支持：

**注解方式（Bean Validation / DTO 层）：**

```java
public class UserDTO {

    // 中国公民：居民身份证
    @NotBlank(message = "身份证号不能为空")
    @ChineseIdCard
    private String idCard;

    // 外国人在华：永久居留身份证（五星卡）
    @NotBlank(message = "永居证号不能为空")
    @ForeignerPermanentResidenceIdentity
    private String prIdCard;
}
```

**链式方式（Service 层 / 动态数据）：**

```java
ValidX validator = ValidX.init()
    .field("居民身份证").isChineseIdCard(idCard)
    .field("五星卡").isForeignerPermanentResidenceIdentity(prIdCard);

if (!validator.passed()) {
    throw new ValidationException(validator.getErrors());
}
```

### 五星卡校验器做了什么

ValidX 的 `ForeignerPermanentResidenceIdentityValidator` 严格按维基百科编码规则实现：

- 正则 `^9\d{17}$`：18 位数字且**首位必须为 9**
- 校验申领地代码（第 2~3 位）必须在省级行政区划代码表内
- 校验出生日期（第 7~14 位）为合法日期、不晚于今天、不早于 1900 年
- 前 17 位加权模 11 计算校验码，与末位比对

### ⚠️ 一个值得注意的边界

维基百科编码规则明确"第 4~6 位为国籍国代码"，且示例为 `124`（加拿大）。ValidX 的五星卡校验器目前**只校验了第 2~3 位省级代码**，国籍国代码需配合 `@NationalityCode(formats = NUMERIC)` 单独复核（详见下一小节）。号码第 4~6 位是三位数字，因此复核时必须限定 NUMERIC 形式——字母代码（如 `CA`）不可能出现在号码中。

### 国籍国代码校验器（落地示例）

为解决"第 4~6 位国籍国代码未校验"的缺口，ValidX 新增了 `@NationalityCode` 注解与 `isNationalityCode()` 链式方法，底层基于 `IsoCountry` 枚举：ISO 3166-1 完整 249 国，每个国家一条枚举常量，**两字母 / 三字母 / 三位数字三种编码绑定在同一常量上**，从结构上杜绝多份数据不同步。

**1. 三种编码形式如何定位**

| 形式 | 示例（加拿大） | 典型场景 | 五星卡号码中 |
|------|------------|---------|------------|
| alpha-2（两字母） | `CA` | SWIFT/BIC、表单国家选择 | ❌ 号码是纯数字 |
| alpha-3（三字母） | `CAN` | 国际航空、联合国文件 | ❌ 同上 |
| numeric（三位数字） | `124` | 五星卡号码第 4~6 位 | ✅ 唯一适用 |

三种形式可通过 `IsoCountry` 互相转换：

```java
IsoCountry.fromAlpha2("CA").get().getNumeric();  // "124"
IsoCountry.fromAlpha3("CAN").get().getAlpha2();  // "CA"
IsoCountry.fromNumeric("999").isPresent();       // false（999 未分配）
```

**2. 注解用法**

```java
// 通用场景：任一形式通过即算通过
@NationalityCode
private String countryCode;               // CA / CAN / 124 均可

// 五星卡复核：仅接受三位数字代码
@NationalityCode(formats = NationalityCode.NationalityCodeType.NUMERIC)
private String nationalityCode;           // 只能填 124，不能填 CA
```

**3. 链式 API 用法**

```java
ValidX.init()
       .isNationalityCode("124")   // 默认三种形式均可
       .isNationalityCode("911124198108030024".substring(3, 6), new NationalityCode.NationalityCodeType[]{NationalityCode.NationalityCodeType.NUMERIC}) // 五星卡第 4~6 位复核
       .passed();
```

**4. 顺带消除的重复数据**

项目原有的 SWIFT/BIC 校验器硬编码了一份 249 国 alpha-2 代码表，本次已改为复用 `IsoCountry.fromAlpha2(...)`——同一份 ISO 3166-1 数据全项目共享，后续新增国家只需改一处。

**5. 五星卡完整校验链示例**

```java
// 维基示例号码：911124198108030024（加拿大 124、北京申领、1981-08-03 出生）
String cardNo = "911124198108030024";
ValidX.init()
       .isForeignerPermanentResidenceIdentity(cardNo)          // 完整五星卡校验（格式+申领地+日期+校验码）
       .isNationalityCode(cardNo.substring(3, 6), new NationalityCode.NationalityCodeType[]{NationalityCode.NationalityCodeType.NUMERIC}) // 第 4~6 位 = 124 加拿大
       .passed();
```

## 八、FAQ

### Q1：五星卡和居民身份证能用同一个正则吗？

**不能。** 首位不同（`9` vs `1~8`），且前 6 位语义完全不同。五星卡的正则是 `^9\d{17}$`，居民身份证是 `^\d{17}[\dX]$` 配合行政区划校验。两者应使用独立校验器。

### Q2：五星卡的出生日期能用 `substring(6, 14)` 提取吗？

**可以。** 五星卡出生日期位置（第 7~14 位）与居民身份证完全一致，直接 `substring(6, 14)` 即可。

### Q3：五星卡的校验码算法和居民身份证一样吗？

**一样。** 权重 `{7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2}` 与模 11 映射表完全相同（维基示例验证通过）。所以 ValidX 内部复用了同一套加权校验逻辑。

### Q4：能用五星卡判断持证人性别吗？

**不要。** 居民身份证倒数第二位奇偶定性别，但五星卡的性别规则**官方未公开**，维基百科仅提供一个样本示例，不足以支撑生产判断。涉及性别的敏感业务请以证件正面登记信息为准。

### Q5：外国人持有五星卡就能当护照用吗？

**不行。** 五星卡是境内居留的身份证件，出入境仍须凭有效护照。它是"身份认证"证件，不是"出入境通行"证件。

### Q6：注册场景外国人该填什么证件？

业务若面向全体在华人员，建议表单设计为**"证件类型 + 证件号码"**两个字段：证件类型选居民身份证/五星卡/护照/港澳台居住证，号码按类型分发校验。这也是金融、政务等合规系统的标准做法。

## 九、总结

我们用一张表回顾全文核心：

| 维度 | 居民身份证 | 五星卡（2023 版） |
|------|-----------|------------------|
| 号码位数 | 18 位 | 18 位 |
| 首位 | 行政区划（1~8） | 外国人标识码 `9` |
| 第 2~3 位 | 省级地址码 | 申领地省级代码 |
| 第 4~6 位 | 市县级地址码 | 国籍国代码（ISO 3166-1） |
| 第 7~14 位 | 出生日期 | 出生日期（位置相同） |
| 第 15~17 位 | 顺序码（含性别） | 顺序码（性别规则未公开） |
| 第 18 位 | 加权模 11 校验码 | 同算法校验码 |
| 面向人群 | 中国公民 | 在华永居外国人 |
| ValidX 校验器 | `@ChineseIdCard` | `@ForeignerPermanentResidenceIdentity` |

三个关键实践：

1. **证件类型分发**：五星卡 ≠ 居民身份证，用独立校验器分别把关，绝不混用
2. **复用而非重写**：日期位置与校验码算法相同，ValidX 内部已复用加权校验逻辑
3. **信息降级**：五星卡不能做省份映射、不能可靠推断性别，解析类能力只适用于居民身份证
