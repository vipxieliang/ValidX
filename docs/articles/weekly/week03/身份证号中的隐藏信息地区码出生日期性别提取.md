# 身份证号中的隐藏信息：地区码、出生日期、性别提取

## 前言

每个中国成年人的钱包里都有一张二代身份证，上面的 18 位号码看起来只是一串数字，但它其实是一份"加密的个人档案"：

- 前 6 位藏着**户籍所在地**的行政区划代码
- 第 7~14 位藏着**出生日期**
- 第 17 位藏着**性别**
- 第 18 位是**校验码**，用来防止号码被篡改或输错

也就是说，只要拿到一个有效的身份证号，即使看不到身份证正面，也能推断出持证人的出生地、生日和性别。这也是为什么很多系统能在注册页"自动填充"生日和性别——它们不是靠用户选择，而是直接从身份证号里提取的。

今天这篇文章，我们就把这串"数字密码"彻底拆开，从结构讲到代码，最后结合 **ValidX** 验证框架，给出生产可用的提取方案。

## 一、身份证号的结构：18 位数字的秘密

18 位身份证号码由 4 个部分组成（GB 11643-1999《公民身份号码》）：

| 位数 | 含义 | 说明 |
|:----:|------|------|
| 第 1~6 位 | **地址码** | 编码对象常住户口所在县（市、旗、区）的行政区划代码 |
| 第 7~14 位 | **出生日期码** | 格式为 `YYYYMMDD`，如 `19900307` |
| 第 15~17 位 | **顺序码** | 同一地址码区域内，对同年同月同日出生的人编订的顺序号 |
| 第 18 位 | **校验码** | 根据前 17 位加权计算得出，0~10 中的一个（10 用 `X` 表示） |

用一张图来表示：

```
110105 19900307 023 1
│──────│ │──────│ │─│ │
 地址码    出生日期  顺序码 校验码
```

其中**顺序码**还有一个隐藏规则：**第 17 位（倒数第二位）为奇数表示男性，偶数表示女性**。这个规则从 15 位老身份证时代延续至今。

### 15 位老身份证的差异

2003 年以前，我国发放的是 15 位一代身份证，结构略有不同：

| 位数 | 含义 | 说明 |
|:----:|------|------|
| 第 1~6 位 | 地址码 | 与 18 位相同 |
| 第 7~12 位 | 出生日期码 | 格式为 `YYMMDD`，**年份只有 2 位**，如 `900307` |
| 第 13~15 位 | 顺序码 | 其中第 15 位为性别码（奇男偶女） |
| - | 无校验码 | 15 位号码没有校验码 |

15 位转 18 位的标准做法是：在出生日期前补上 `19`，再计算校验码。后面我们会看到 15 位号码在提取信息时需要特殊处理。

## 二、提取地区码：你的身份证"出生"在哪里

### 编码规则

地址码是 6 位行政区划代码：

- 前 2 位：**省级**代码（省、自治区、直辖市、特别行政区）
- 中间 2 位：**市级**代码
- 后 2 位：**区县级**代码

对绝大多数业务场景来说，提取到"省级"就够用了。**省级代码近 40 年几乎没有变动**，是最可靠的维度。34 个省级行政区的代码映射如下（与 ValidX `ChineseIdCardValidator` 内置映射一致）：

|:----:|------|:----:|------|:----:|------|
| 11 | 北京市 | 32 | 江苏省 | 52 | 贵州省 |
| 12 | 天津市 | 33 | 浙江省 | 53 | 云南省 |
| 13 | 河北省 | 34 | 安徽省 | 54 | 西藏自治区 |
| 14 | 山西省 | 35 | 福建省 | 61 | 陕西省 |
| 15 | 内蒙古自治区 | 36 | 江西省 | 62 | 甘肃省 |
| 21 | 辽宁省 | 37 | 山东省 | 63 | 青海省 |
| 22 | 吉林省 | 41 | 河南省 | 64 | 宁夏回族自治区 |
| 23 | 黑龙江省 | 42 | 湖北省 | 65 | 新疆维吾尔自治区 |
| 31 | 上海市 | 43 | 湖南省 | 71 | 台湾省 |
| - | - | 44 | 广东省 | 81 | 香港特别行政区 |

### 代码实现

提取省份只需要一行 `substring`：

```java
public String extractProvinceCode(String idCard) {
    return idCard.substring(0, 2);
}
```

配合映射表即可得到省份名称：

```java
private static final Map<String, String> PROVINCE_MAP = new HashMap<>();
static {
    PROVINCE_MAP.put("11", "北京市");
    PROVINCE_MAP.put("12", "天津市");
    // ... 全部 34 个省级行政区
}

public String extractProvinceName(String idCard) {
    return PROVINCE_MAP.get(idCard.substring(0, 2));
}
```

### ⚠️ 注意事项

1. **行政区划会调整**：1997 年重庆从四川划出成为直辖市，1988 年海南建省，这些事件都会导致老号码的 6 位地址码与现行区划表对不上。**前 2 位省级代码基本不变，但 6 位完整地址码需要维护最新区划数据**。
2. **身份证编码 ≠ 现居地**：地址码记录的是**签发时的户籍所在地**，户口迁移后身份证号并不改变，所以别用它判断用户现在的常住地。
3. 如果要精确到市、县，需要引入完整的行政区划库（6000+ 条记录），且要跟随民政部区划调整更新。

## 三、提取出生日期：生日不用用户填了

### 编码规则

- 18 位：第 7~14 位，格式 `YYYYMMDD`
- 15 位：第 7~12 位，格式 `YYMMDD`，年份需要补 `19`

```java
public String extractBirthDateStr(String idCard) {
    if (idCard.length() == 18) {
        return idCard.substring(6, 14);   // 19900307
    }
    return "19" + idCard.substring(6, 12); // 15位补19 → 19900307
}
```

### 更严谨的解析：转成 LocalDate

字符串直接返回不够严谨，推荐解析为 `LocalDate`，这样后续可以做日期合法性校验和年龄计算：

```java
public LocalDate extractBirthDate(String idCard) {
    String birthStr = idCard.length() == 18
        ? idCard.substring(6, 14)
        : "19" + idCard.substring(6, 12);

    // 使用 STRICT 模式：严格校验闰年、月份天数（如 2 月 29 日）
    DateTimeFormatter formatter = DateTimeFormatter.ofPattern("yyyyMMdd")
        .withResolverStyle(ResolverStyle.STRICT);

    return LocalDate.parse(birthStr, formatter);
}
```

### ⚠️ 注意事项

1. **必须用严格模式**：`LocalDate.parse` 默认的 SMART 模式会把 `20230230` 这种不存在的日期"自动修正"成 `2023-02-28`，导致提取结果与真实信息不符。用 `ResolverStyle.STRICT` 才能保证提取的就是原样日期。
2. **合理性边界**：生产环境还应该校验日期不晚于今天（身份证的出生日期不可能在未来）、不早于 1900 年（一代身份证签发上限）。
3. **算年龄别用年份相减**：`当前年份 - 出生年份` 算出来的是"虚岁"，正确做法是 `Period.between(birthDate, LocalDate.now()).getYears()`，这才是"周岁"。

## 四、提取性别：倒数第二位，奇男偶女

### 编码规则

顺序码的第 17 位（15 位身份证是第 15 位）是性别码：**奇数 = 男，偶数 = 女**。

无论 15 位还是 18 位，统一取**倒数第二位**即可：

```java
public String extractGender(String idCard) {
    // 倒数第二位，18位是第17位，15位是第15位
    int genderCode = idCard.charAt(idCard.length() - 2) - '0';
    return genderCode % 2 == 1 ? "男" : "女";
}
```

一行代码，就这么简单。

### ⚠️ 注意事项

性别码是**编码规则层面的推断**，正常情况下与持证人生理性别一致。但极端情况下（户籍登记失误、性别变更后未换证等）可能存在不一致，涉及性别鉴定的敏感业务（如保险核保）不要仅凭身份证号下结论。

## 五、提取前必须做的一件事：先校验

信息提取的前提是号码本身有效。**先校验、再提取**，顺序不能反：

1. 无效号码提取出来的生日、性别、省份全是垃圾数据
2. 校验码（第 18 位）是防呆设计，能挡住绝大多数人为输错

校验码算法是一个加权求和的数学过程（详见本系列的《身份证号校验码算法详解：权重计算的数学原理》），核心是：前 17 位数字依次乘以权重 `{7,9,10,5,8,4,2,1,6,3,7,9,10,5,8,4,2}`，求和后对 11 取余，余数映射到校验码 `{'1','0','X','9','8','7','6','5','4','3','2'}`。

这里不展开算法细节，我们直接用 ValidX 来把关：

```java
// 注解方式：格式 + 校验码 + 生日合法性 + 省份合法性，一行搞定
@ChineseIdCard
private String idCard;
```

```java
// 链式方式
ValidX validator = ValidX.init()
    .isChineseIdCard(idCard);

if (!validator.passed()) {
    throw new IllegalArgumentException("身份证号不合法: " + validator.getErrors());
}
```

`@ChineseIdCard` 已经内置了省份编码、出生日期、校验码的全套校验，校验通过后再提取，数据才是可信的。

## 六、完整工具类：IdCardInfoExtractor

把上面的逻辑整合成一个可复用的工具类（兼容 15/18 位，内部自带校验）：

```java
import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.ResolverStyle;
import java.util.HashMap;
import java.util.Map;

/**
 * 身份证号信息提取工具类
 * 支持 15 位 / 18 位身份证号，提取：地区码、出生日期、性别
 */
public final class IdCardInfoExtractor {

    /** 省级行政区代码映射 */
    private static final Map<String, String> PROVINCE_MAP = new HashMap<>();
    static {
        PROVINCE_MAP.put("11", "北京市");
        PROVINCE_MAP.put("12", "天津市");
        PROVINCE_MAP.put("13", "河北省");
        PROVINCE_MAP.put("14", "山西省");
        PROVINCE_MAP.put("15", "内蒙古自治区");
        PROVINCE_MAP.put("21", "辽宁省");
        PROVINCE_MAP.put("22", "吉林省");
        PROVINCE_MAP.put("23", "黑龙江省");
        PROVINCE_MAP.put("31", "上海市");
        PROVINCE_MAP.put("32", "江苏省");
        PROVINCE_MAP.put("33", "浙江省");
        PROVINCE_MAP.put("34", "安徽省");
        PROVINCE_MAP.put("35", "福建省");
        PROVINCE_MAP.put("36", "江西省");
        PROVINCE_MAP.put("37", "山东省");
        PROVINCE_MAP.put("41", "河南省");
        PROVINCE_MAP.put("42", "湖北省");
        PROVINCE_MAP.put("43", "湖南省");
        PROVINCE_MAP.put("44", "广东省");
        PROVINCE_MAP.put("45", "广西壮族自治区");
        PROVINCE_MAP.put("46", "海南省");
        PROVINCE_MAP.put("50", "重庆市");
        PROVINCE_MAP.put("51", "四川省");
        PROVINCE_MAP.put("52", "贵州省");
        PROVINCE_MAP.put("53", "云南省");
        PROVINCE_MAP.put("54", "西藏自治区");
        PROVINCE_MAP.put("61", "陕西省");
        PROVINCE_MAP.put("62", "甘肃省");
        PROVINCE_MAP.put("63", "青海省");
        PROVINCE_MAP.put("64", "宁夏回族自治区");
        PROVINCE_MAP.put("65", "新疆维吾尔自治区");
        PROVINCE_MAP.put("71", "台湾省");
        PROVINCE_MAP.put("81", "香港特别行政区");
        PROVINCE_MAP.put("82", "澳门特别行政区");
    }

    /** 身份证校验权重（前 17 位） */
    private static final int[] WEIGHTS = {7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2};
    /** 校验码映射表 */
    private static final char[] CHECK_CODES = {'1', '0', 'X', '9', '8', '7', '6', '5', '4', '3', '2'};

    /** 严格日期解析：拒绝 20230230 这类不存在的日期 */
    private static final DateTimeFormatter BIRTH_FORMATTER =
        DateTimeFormatter.ofPattern("yyyyMMdd").withResolverStyle(ResolverStyle.STRICT);

    private IdCardInfoExtractor() {
    }

    /**
     * 提取身份证号中的信息
     *
     * @param idCard 15 位或 18 位身份证号
     * @return 提取结果
     * @throws IllegalArgumentException 号码格式不合法
     */
    public static IdCardInfo extract(String idCard) {
        if (idCard == null || idCard.trim().isEmpty()) {
            throw new IllegalArgumentException("身份证号不能为空");
        }

        String normalized = idCard.trim().toUpperCase();
        if (!isValid(normalized)) {
            throw new IllegalArgumentException("身份证号不合法: " + idCard);
        }

        // 统一转为 18 位处理
        String id18 = normalized.length() == 15 ? convert15To18(normalized) : normalized;

        // 1. 地区码（前 2 位 → 省份）
        String provinceCode = id18.substring(0, 2);
        String provinceName = PROVINCE_MAP.getOrDefault(provinceCode, "未知");

        // 2. 出生日期（第 7~14 位）
        LocalDate birthDate = LocalDate.parse(id18.substring(6, 14), BIRTH_FORMATTER);

        // 3. 性别（倒数第二位，奇男偶女）
        int genderCode = id18.charAt(id18.length() - 2) - '0';
        String gender = genderCode % 2 == 1 ? "男" : "女";

        return new IdCardInfo(id18, provinceCode, provinceName, birthDate, genderCode, gender);
    }

    /**
     * 校验身份证号是否合法（格式 + 省份 + 日期 + 校验码）
     */
    public static boolean isValid(String idCard) {
        String id = idCard.trim().toUpperCase();
        if (!id.matches("\\d{17}[0-9X]") && !id.matches("\\d{15}")) {
            return false;
        }

        String id18 = id.length() == 15 ? convert15To18(id) : id;

        // 省份校验
        if (!PROVINCE_MAP.containsKey(id18.substring(0, 2))) {
            return false;
        }

        // 日期校验（严格模式，自动拒绝非法日期）
        try {
            LocalDate.parse(id18.substring(6, 14), BIRTH_FORMATTER);
        } catch (Exception e) {
            return false;
        }

        // 校验码校验
        int sum = 0;
        for (int i = 0; i < 17; i++) {
            sum += (id18.charAt(i) - '0') * WEIGHTS[i];
        }
        return CHECK_CODES[sum % 11] == id18.charAt(17);
    }

    /**
     * 15 位身份证号转为 18 位：出生年份前补 "19" 并计算校验码
     */
    private static String convert15To18(String id15) {
        String id17 = id15.substring(0, 6) + "19" + id15.substring(6);
        int sum = 0;
        for (int i = 0; i < 17; i++) {
            sum += (id17.charAt(i) - '0') * WEIGHTS[i];
        }
        return id17 + CHECK_CODES[sum % 11];
    }
}
```

```java
import java.time.LocalDate;

/**
 * 身份证号提取结果
 */
public class IdCardInfo {

    /** 标准化后的 18 位身份证号 */
    private final String idCard;
    /** 省级行政区代码 */
    private final String provinceCode;
    /** 省份名称 */
    private final String provinceName;
    /** 出生日期 */
    private final LocalDate birthDate;
    /** 性别码（第 17 位数字） */
    private final int genderCode;
    /** 性别：男 / 女 */
    private final String gender;

    public IdCardInfo(String idCard, String provinceCode, String provinceName,
                      LocalDate birthDate, int genderCode, String gender) {
        this.idCard = idCard;
        this.provinceCode = provinceCode;
        this.provinceName = provinceName;
        this.birthDate = birthDate;
        this.genderCode = genderCode;
        this.gender = gender;
    }

    public String getIdCard() { return idCard; }
    public String getProvinceCode() { return provinceCode; }
    public String getProvinceName() { return provinceName; }
    public LocalDate getBirthDate() { return birthDate; }
    public int getGenderCode() { return genderCode; }
    public String getGender() { return gender; }

    /** 计算周岁年龄 */
    public int getAge() {
        return java.time.Period.between(birthDate, LocalDate.now()).getYears();
    }

    @Override
    public String toString() {
        return "IdCardInfo{" +
            "idCard='" + idCard + '\'' +
            ", province=" + provinceName +
            ", birthDate=" + birthDate +
            ", gender='" + gender + '\'' +
            '}';
    }
}
```

## 七、结合 ValidX 的最佳实践

手动提取 + 手动校验容易出错，生产环境推荐 **ValidX 负责校验、提取类负责解析** 的分工模式。

### 方案 1：注解方式（DTO 层）

```java
public class UserDTO {

    @NotBlank(message = "身份证号不能为空")
    @ChineseIdCard
    private String idCard;

    // 直接从身份证提取年龄校验（18~65 岁），不用单独传生日字段
    @Age(min = 18, max = 65, fromIdCard = true)
    private String idCardForAge;

    // getters and setters...
}
```

`@ChineseIdCard` 先保证号码合法，`@Age(fromIdCard = true)` 再从中提取出生日期计算年龄并校验范围——整个流程零手写代码。

### 方案 2：链式方式（Service 层）

处理 Map、JSON 等动态数据时用链式 API：

```java
@Service
public class UserService {

    public void register(Map<String, Object> data) {
        Object idCard = data.get("idCard");

        ValidX validator = ValidX.init()
            .field("身份证号").isChineseIdCard(idCard)
            .field("年龄").isAge(idCard, 18, 65, true);  // 从身份证提取年龄校验

        if (!validator.passed()) {
            throw new ValidationException(validator.getErrors());
        }

        // 校验通过，提取信息入库
        IdCardInfo info = IdCardInfoExtractor.extract(idCard.toString());
        saveUser(info);
    }
}
```

### 实战：注册时自动填充生日、性别、省份


用户注册时只需填身份证号，生日、性别、户籍省份全部自动带出——这就是"提取"最大的产品价值：**减少填写项，提升转化率**。

## 八、注意事项与隐私合规

### 1. 身份证号是敏感个人信息

根据《个人信息保护法》，身份证号属于**敏感个人信息**，其中的地区码、出生日期、性别同样敏感。提取后要注意：

- **脱敏展示**：列表页只显示 `110105********0231` 这类脱敏格式
- **加密存储**：数据库建议使用国密 SM4 等算法加密存储
- **最小化**：只提取业务真正需要的字段，不要全量留存
- **日志脱敏**：日志、异常信息中不要打印完整身份证号

### 2. 提取 ≠ 事实

身份证号反映的是**签发登记时的信息**，可能滞后于现实：

- 性别推断在极少数极端情况下可能与实际不符
- 出生日期是登记日期，理论上应与真实出生日期一致
- 地区码反映签发地而非现居地

### 3. 15 位兼容

虽然一代身份证已停用，但存量系统里可能还有 15 位数据。提取时统一按"补 19 + 算校验码"转 18 位处理，避免两套逻辑。

### 4. 证件类型边界：别拿身份证规则套其他证号

本文的解析规则**只适用于中国公民居民身份证**（GB 11643-1999《公民身份号码》）。以下几种证件号码同样 18 位、外观相似，但编码体系完全不同，**不能用 `substring(0, 6)` 提取地区码，性别奇偶规则也不能跨证件套用**：

| 证件 | 号码特征 | 权威依据 |
|------|---------|---------|
| 中国公民居民身份证 | 18 位，前 6 位为行政区划代码（首位 1~8） | GB 11643-1999《公民身份号码》 |
| 外国人永久居留身份证（"五星卡"） | 18 位（17 位数字 + 1 位校验位），**首位固定为 `9`**（外国人标识码），并编列国籍国代码、申领地代码 | 2023-12-01 启用（国家移民管理局公告），首位 `9` 见中国新闻网等媒体报道 |
| 港澳台居民居住证 | 18 位，**以 `8` 开头**，前 6 位地址码为 `810000`（香港）/ `820000`（澳门）/ `830000`（台湾） | 《港澳台居民居住证申领发放办法》（国办发〔2018〕81 号） |

关于"五星卡"号码内部字段，官方公开资料仅明确了"首位 `9` + 编列国籍代码、申领地代码"，逐位结构未逐位公布。本系列项目按通行口径实现：`9 + 2 位申领地代码 + 3 位国籍国代码 + 8 位出生日期 + 3 位顺序码 + 1 位校验码`，其中出生日期位置（第 7~14 位）与居民身份证恰好一致，但**前 6 位不是行政区划代码**，不能映射省份。

**实践建议**：按证件类型分发校验，切勿混用。ValidX 已内置区分——中国公民用 `@ChineseIdCard`，外国人在华用 `@ForeignerPermanentResidenceIdentity`，链式对应 `isChineseIdCard()` / `isForeignerPermanentResidenceIdentity()`；若入籍中国，持普通居民身份证，解析规则与本文完全一致。

## 九、FAQ

### Q1：提取出生日期后，年龄应该怎么算？

用 `Period.between(birthDate, LocalDate.now()).getYears()` 计算**周岁**。直接减年份得到的是虚岁，在 18 岁/60 岁这类临界点上会出错。

### Q2：为什么提取要用严格日期模式？

`LocalDate.parse` 默认 SMART 模式会自动"修正"非法日期（如 `20230230` → `2023-02-28`），会把脏数据当有效数据提取。`ResolverStyle.STRICT` 会直接拒绝非法日期，保证提取结果的真实性。

### Q3：15 位身份证号提取时要注意什么？

出生日期只占第 7~12 位且年份只有 2 位，需要补 `19` 前缀；性别位是第 15 位（而非第 17 位）。统一先转 18 位再提取，代码只需一套逻辑。

### Q4：完整市县级地址码怎么提取？

前 2 位省份映射基本稳定，但 3~6 位市县代码会随行政区划调整（如 1997 重庆直辖、1988 海南建省）失效。要精确到市县，需维护民政部区划库并定期更新。

### Q5：ValidX 能直接提供提取 API 吗？

ValidX 目前定位是**校验**（`@ChineseIdCard`、`@Age(fromIdCard = true)`、链式 `isChineseIdCard` / `isAge`），信息提取推荐使用本文的 `IdCardInfoExtractor` 或类似工具类，与 ValidX 校验组合使用。

## 十、总结

身份证号是一份编码精巧的"数字档案"，我们用一张表回顾全文：

| 信息 | 位置（18 位） | 位置（15 位） | 提取方法 |
|------|--------------|--------------|---------|
| 省级地区 | 第 1~2 位 | 第 1~2 位 | `substring(0, 2)` + 映射表 |
| 市县级地区 | 第 3~6 位 | 第 3~6 位 | 需维护区划库 |
| 出生日期 | 第 7~14 位 | 第 7~12 位（补 19） | `substring` + 严格模式解析 |
| 性别 | 第 17 位（倒数第 2） | 第 15 位（倒数第 2） | 取倒数第二位，奇男偶女 |
| 校验码 | 第 18 位 | 无 | 加权求和取余（先校验再提取） |

三个关键实践：

1. **先校验、再提取**：用 `@ChineseIdCard` 或链式 `isChineseIdCard` 把关，提取才有意义
2. **15/18 位统一处理**：15 位先补 `19` 并计算校验码转 18 位，提取逻辑只写一套
3. **合规第一**：身份证号及提取信息属敏感个人信息，加密存储 + 脱敏展示 + 最小化使用
